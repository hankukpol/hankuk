# 학원별 독립 운영 템플릿 — 필수 개발 원칙

운영자 확정: 2026-09-14. 모든 신규 개발·수정·리뷰에 적용한다. 아래 내용은 **개발 요구사항**이며 현재 구현이 모두 완료되었다는 뜻은 아니다.

## 제품의 기본 개념

스터디홀은 여러 학원에 납품하는 범용 제품이다. 납품받은 학원 관리자가 개발자 도움 없이 설정 화면에서 자신의 운영 방식을 구성하고 실제 업무에 반영할 수 있어야 한다.

경찰파트에서 처음 구현했더라도 경찰의 시간표·규정·점수·장소를 공통 서비스에 고정하지 않는다. 특정 학원 요청은 공통 기능과 해당 학원의 설정 값으로 분리한다.

## 필수 설정 범위

- 시간표: 교시 이름·시작/종료·필수 여부·적용 요일·운영일
- 출결: 출석·수업·사유결석 처리 기준, 실제 도착 시각에 따른 지각 분 기준, 일괄 처리·관리자 확정 방식
- 상벌점: 항목·활성 여부·점수·연결 규칙·월별 집계·경고 임계값/문구·자동 부여/마감
- 휴무·반휴권·병가: 제공 한도, 차감/면제 기준, 미사용 정산, 적용 기간
- 개근: 대상 교시·요일·기간·예외·지급 점수 및 자동화
- 휴대폰: 체크 대상, 반출 시간·장소·승인 방식·반납 기준·반복 기준
- 좌석: 강의실·행/열·통로·좌석 이름·활성 여부. 좌석 배정은 운영 데이터이며 템플릿에 넣지 않는다.
- 수납: 수강료 계획·기간·금액·수납 항목. 학생별 약정·납부 내역은 별도로 보존한다.
- 시험: 종류·과목·배점·시작일·요일·휴강일·성적 집계 및 상벌점 연결

## 저장·복사·적용 계약

1. 공통 템플릿 가져오기와 자체 템플릿 생성·편집을 제공한다.
2. 적용은 대상 학원에 설정을 복사하는 행위다. 이후 원본이나 다른 학원의 수정은 자동 전파하지 않는다.
3. 모든 조회·저장·연결 참조는 현재 학원의 division_id로 제한한다. 참조 ID만 받아서 다른 학원 규칙·교시를 연결하지 않는다.
4. 적용 전 변경 전/후 미리보기, 적용일, 요청자·적용 결과를 포함한 이력을 제공한다. 예약한 내용과 현재 설정이 충돌하면 조용히 덮어쓰지 않는다.
5. 설정 화면의 값과 실제 판정·계산·저장·자동 마감이 같은 설정을 사용해야 한다. 화면만 추가하거나 숫자를 표시만 하는 것으로 완료 처리하지 않는다.
6. 실제 도착 시각과 직원의 저장 시각을 구분한다. 일괄 출석 저장 시간을 도착 시간으로 간주해 지각을 부여하지 않는다.
7. 신규 자동화는 관리자가 적용 조건을 정하기 전 임의로 활성화하지 않는다. 특정 학원 설정을 전체 학원에 일괄 적용하지 않는다.

## 기존 기록과 개인정보 보호

- 학생·이름·수험번호·연락처·로그인 정보·직원 계정·선택자습 신청·실제 출결/성적/점수/납부 기록·좌석 배정을 템플릿에 복사하지 않는다.
- 적용 과정에서 기존 출결·상벌점·성적·납부 내역을 삭제하거나 재작성하지 않는다. 이미 부여한 점수와 약정 금액은 설정 값 변경만으로 소급 변경하지 않는다.
- 사용 중인 좌석의 삭제·비활성화·위치 변경은 배정 보호 검증을 거친다.
- 과거 날짜의 판정 및 자동 마감은 해당 날짜에 적용되는 규정을 사용한다. 변경한 규정을 과거에 일괄 소급하지 않는다.

## 완료 전 확인

서로 다른 두 학원의 시간표·지각 기준·점수·휴무/반휴·시험 요일로 서로 다른 계산 결과를 확인한다. 접근 차단, 템플릿 복사 후 독립 수정, 적용일/예약/이력, 기존 기록과 좌석 배정 보존을 검증한다. 관리자·조교·학생 화면이 같은 업무 데이터를 보도록 한다.

실제 동작하는 설정과 안내 목적으로만 사용하는 규정을 구분해 문서화한다. 미연결 항목은 미완료로 보고한다.

## 작업 및 배포 승인

기본은 단일 에이전트가 구현·검증까지 진행한다. 다른 세션의 작업은 보존한다.

**Git 커밋·푸시·운영 배포·운영 DB 반영은 사용자의 해당 작업에 대한 명시적 승인 후에만 진행한다.** 과거 배포 승인을 새 작업의 승인으로 재사용하지 않는다. 로컬 구현·검증과 운영 반영을 구분해 보고한다.

## 과거 적용일 정정 (운영자 요청, 2026-09-15)

관리자는 공통 설정 변경·템플릿·선택자습 신청·등원 설정에 과거 적용일을 지정할 수 있다. 과거 또는 오늘은 즉시 적용하고 미래만 예약한다. 화면뿐 아니라 서버 검증과 날짜별 설정 조회에도 동일하게 반영한다. 적용 이력은 변경 전후를 남기며, 나중에 입력한 과거 정정은 해당 날짜부터 변경한 항목에만 반영한다. 기존 출결·수납·점수 원장은 설정 저장만으로 일괄 재작성하지 않는다. 이후 해당 날짜의 판정·재계산은 정정한 설정을 사용한다. 운영 데이터 일괄 재산정은 별도 작업으로 구분한다.

## 적용 완료 이력의 날짜 정정

설정 템플릿의 적용 이력에서 `적용일 정정`을 사용한다. 설정 내용이 같아도 날짜만 정정할 수 있다. 원본 변경 전후 스냅샷·생성 순서는 유지하고, 이전/정정 날짜·사유·관리자·정정 시각을 별도 설정 이력에 기록한다. 적용 완료 항목은 오늘 또는 과거로 정정하며 미래 변경은 예약 기능을 사용한다. 기존 출결·점수·수납·좌석 배정은 자동 재작성하지 않는다. 이미 채점된 시험의 출석 재동기화는 별도 작업이다.
