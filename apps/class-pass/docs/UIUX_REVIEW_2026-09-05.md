## 결론과 범위

현재 관리자 디자인을 유지하면서 입력 보호, 정산 가독성, 표의 학생 식별, 작은 화면의 탐색 밀도를 보완해야 한다. 아래는 실제 재현한 문제와 개선 제안을 구분한 결과다. 이 문서는 **리뷰 결과이며 수정 완료 보고서가 아니다.**

- 기준: 현재 `DESIGN.md`, 관리자 공통 CSS와 해당 화면 소스.
- 직접 확인: 로컬 경찰 관리자 대시보드, 강좌 8의 수강생 명단·등록·메모·수납/환불 모달·기본 설정, 일일 정산.
- 화면 크기: 명단 1280×900 / 768×900 / 390×844, 등록 및 수납 drawer 1280×900, 메모 390×844, 대시보드·정산·설정 1280×900.
- 추가 소스 확인: 월별 정산, 엑셀 가져오기, 좌석·과목 설정의 그리드, 공통 페이지·모달·폼·표 스타일.
- 등록에서는 임시 이름만 입력하고 닫기/재열기로 작성 중 입력 소실을 확인했다. 등록·결제·메모 저장, 삭제, 정산 확인, 운영 DB 변경은 하지 않았다.
- 앱 코드·기존 디자인 문서는 수정하지 않았다. 이 리뷰와 검증 기록만 추가했다. 커밋·푸시·배포 없음.
- 로컬 서버가 검토 도중 일시적으로 연결을 거부한 뒤 다시 응답했고, 작업 중 화면 갱신도 있었다. 해당 현상을 운영 장애나 확정 UI 버그로 분류하지 않았다. 병행 변경 중인 작업 트리의 특정 시점 리뷰다.
- 모든 강좌·직원·팝업·학생/직원 전용 화면과 모든 실패 상태를 브라우저에서 전수 검증한 것은 아니다. 실기기 가상 키보드, 스크린리더 실제 사용, 운영 성능, 결제 저장 정확성은 이번 리뷰 범위 밖이다.

## R01. 등록창의 미저장 입력 보호

### 재현

1. 강좌 → 수강생 → `+ 수강생 등록`.
2. 이름에 테스트용 문구 입력. 등록 버튼은 누르지 않음.
3. 오른쪽 위 닫기 클릭: 확인 대화상자 없이 닫힘.
4. 다시 등록창 열기: 이름이 빈 문자열로 초기화됨.

모달을 닫는 동작 자체가 등록 기록을 삭제하는 것은 아니다. **아직 저장하지 않은 작성 내용이 소실되는 문제**다. 여러 강좌의 무료 여부·금액·할인 사유를 편집하는 긴 업무에서는 재입력 부담이 커진다.

근거:

- `src/app/(admin)/dashboard/courses/[id]/students/course-students-page-client.tsx:780`: 모달 닫기에서 바로 `setPanel('none')`.
- 같은 파일 `:2665`: 재열기에서 `setCreateForm(emptyForm(...))`, 결제폼·강좌 묶음 상태 초기화.
- 같은 파일 `:2755`: 드래그 닫기도 동일 종료 경로.
- `docs/REGISTRATION_WORKFLOW.md:53`: 미저장 닫기 보호가 후속 과제로 남아 있음.
- 반대로 메모는 `EnrollmentMemoDialog.tsx:35`의 dirty 검사 및 `:41`의 닫기 확인이 이미 있음.

권장: X·취소·Esc·배경 클릭·드래그 종료를 동일한 `requestClose`로 모으고, 변경된 경우 `계속 작성 / 변경 내용 버리고 닫기`를 제공한다. 초기 상태나 저장 완료 후에는 불필요한 확인을 띄우지 않는다. 학생 개인정보를 브라우저 영구 저장소에 자동 보관하는 방식은 별도 보안 판단 없이 도입하지 않는다.

검증 기준: 이름뿐 아니라 추가 강좌, 무료/유료 전환, 금액, 할인 사유, 수납 항목 변경에도 동작해야 한다. 수납·편집 폼도 동일 기준으로 후속 점검하되, 이번 브라우저 소실 재현은 등록창에 한정한다.

## R06. 설정 폼 레이블 연결 누락

강좌 기본정보의 강좌명·유형·상태·정렬순서 등 입력은 눈에 보이는 레이블이 있으나, 실제 input/select의 `labels`가 빈 배열이며 `aria-label`/`aria-labelledby`도 없다. 접근성 트리에서도 ‘강좌명’ 입력이 이름 없는 textbox로 표시되었다. 일부 placeholder가 이름처럼 잡히더라도 명시적 레이블 연결을 대체하지 못한다.

근거: `course-detail-page-client.tsx:542` 이후 label과 input이 형제이며 htmlFor/id가 없음. 체크박스는 감싸는 label이 있어 정상 연결된 항목도 있으므로 전체 폼이 모두 같다고 일반화하지 않는다.

권장: 공통 FormField로 레이블·필수 표시·도움말·오류 연결을 표준화한다. 레이블 클릭 시 해당 입력으로 초점이 이동하고, 보조기술에서 ‘강좌명’ 등 실제 이름으로 식별되어야 한다.

## R07. 작은 위험 텍스트의 색 대비

390px 메모 모달에서 활성 ‘메모 삭제’는 15px / 600, 글자 `#ff3b30`, 배경 `#ffffff`였다. 계산 대비는 3.547137959:1이다. 일반 크기 텍스트의 4.5:1 기준보다 낮다. 비활성 ‘메모 저장’은 이 지적의 대상이 아니다.

- 근거: `admin.css:39` danger 토큰, `:392` `.admin-memo-delete`.
- 기준: [W3C WCAG 2.2 — Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

권장: 현재 포인트/브랜드 색을 전부 바꾸지 말고, 작은 위험 글자용 진한 의미 색상 토큰을 별도로 정의한다. 삭제 메뉴·인라인 오류·경고 문구도 동일 목적에 맞춰 검증한다. 이 결과는 특정 활성 버튼의 대비 검사이며 전체 접근성 인증 결과가 아니다.

근거: `dashboard/page.tsx:263`의 actionCards가 article/문구/숫자로만 구성됨.

권장: 경고 클릭 → 해당 조건의 강좌 목록 또는 관련 운영 페이지로 연결한다. 1개 대상이면 바로 이동하고, 여러 개면 대상 목록을 제공한다. 클릭 즉시 출석 시작 등 운영 상태를 바꾸는 기능으로 만들지 않는다. 현재 동작이 고장 난 것은 아니며 업무 동선 개선이다.

## 확인한 유지 사항과 검증 한계

- 직접 본 화면에서 주 탭은 폴더형, 서브 탭은 직선 밑줄이었다. 수강생이 첫 탭, 설정이 마지막이었다.
- 정산 표 헤더는 가운데, 강좌명은 왼쪽, 금액은 오른쪽, 기타 일반 셀은 가운데로 측정되었다. 정산 검색과 표의 왼쪽 시작은 모두 x=288이었다.
- 메모 모달은 학생·강좌명과 작성/수정일을 표시했고, 390px에서 X·삭제·취소·저장 버튼은 겹치지 않았다. 학생 식별과 강좌별 메모라는 구조는 유지해야 한다.
- 등록 drawer에 납부 금액·입력 수납액의 고정 요약이 이미 있다. 이를 미구현 사항으로 다시 제안하지 않는다.
- `pnpm verify:admin-presentation`: 75개 관리자/결제 소스 대상 통과. 내부 코드 표시 규칙 등 정적 검사이며 75개 화면을 모두 브라우저 검사했다는 뜻은 아니다.
- 디자인 토큰 검사: 미선언 색상 0건, 2px 한 건을 spacing으로 감지. 실제로는 `admin.css:127`의 서브 탭 border-bottom이며 `DESIGN.md:221`의 명시된 2px 직선 밑줄이다. 검사기의 정규식 오탐으로 판정했고, 이를 4px로 바꾸거나 검사 결과를 전체 UI 통과로 취급하지 않았다.
- Lighthouse/운영 부하/네트워크 실패 주입은 수행하지 않았다. 전체 모달·권한·저장 워크플로우의 기능 합격 판정은 아니다.
