2026-09-05. 기존 리뷰 S1/C1–C4/D1–D6 중 루트 담당 C3/C4/D4/D6. 운영 반영 없음.

## 변경

- `course-students-page-client.tsx`: 강좌·탭·요청 세대별 매트릭스 조회를 구분한다. 이전 응답/오류/finally가 새 화면을 덮지 못한다. 준비되지 않은 표는 쓰기를 차단하며, 재조회 실패 후 같은 탭 클릭으로 다시 조회할 수 있다.
- `students-matrix-panel.tsx`: 로딩/사용 불가와 실제 배부 진행을 구분한다. 비활성 입력에 잘못된 진행 문구를 붙이지 않는다. 조회 실패 안내와 재시도 경로를 제공한다.
- 배정·수령·취소의 응답 유실/잘못된 JSON/불완전한 성공 응답은 실패로 단정하여 체크를 되돌리지 않는다. 서버 상태를 다시 조회한다. 재조회가 실패하면 불확실한 표에서 추가 쓰기를 막는다.
- 부분 성공·캐시 경고는 저장 결과와 구분한다. 실제 저장 시각만 표시하고 클라이언트 현재 시각을 수령 시각으로 만들어 넣지 않는다.
- `receipt-matrix/route.ts`와 자료 관련 getter: 실제 반환량만큼 offset을 이동하고 빈 페이지까지 조회한다. 서버 상한 300에서도 1,200행 전체를 읽는다.
- `distribution/cache.ts`, 배부 service/manual/undo/scan: 저장 이후 캐시 실패는 `refreshRequired`/warning으로 반환한다. RPC 전송 실패와 후속 로그 조회 실패가 이미 성공한 자료 목록을 지우지 않는다.

공유 파일의 수강등록·할인·정산·관리자 디자인 변경은 다른 작업 소유다. 본 작업은 해당 변경을 되돌리지 않았다.

## RED → GREEN

실제 라우트/React 컴포넌트에서 다음 실패를 먼저 관측했다: cap300 조회 누락, 캐시 실패에 성공 결과 유실, 늦은 배부자료 응답이 교재 탭을 덮음, 저장 후 네트워크/JSON 응답 유실에 재조회 없음, 재조회 실패 후 오래된 체크박스가 쓰기 가능.

동일 assertion을 유지하여 수정 후 통과했다. 수동 배부·수령 취소의 네트워크 유실/캐시 경고 두 추가 시나리오도 실제 관리자 페이지를 렌더링하여 검증했다. DB 서버 경계는 테스트 대역이며, 실제 DB 동시성은 별도 CJS 검증이다.

최종 관리자 파일: 부모 1 + 하위 시나리오 6 = 7 passed. 독립 검토자의 집중 7파일은 31 passed. 전체 TS/TSX 463 passed, CJS 30 passed, 모두 fail/skip 0. opt-in `admin-memo-local`은 자료 범위 밖 별도 DB 테스트여서 전체 TS 목록에서 제외했다.
