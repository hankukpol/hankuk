확인일: 2026-10-01 KST. 로컬 코드 HEAD `a2c1f86`. 사용자 요청은 오류 확인이며, 제품 코드·운영 설정·출결·성적·상벌점 수정 또는 배포 요청은 아니다.

## 1. 화면 오류의 원인

| 조건 | 10월 1일 기준 확인 결과 |
|---|---|
| 실제 시험일 | 문항분석표 내부 시험일자 `2026-10-01`, 목요일(4) |
| 관리규정 | 스키마 유효, 사용 가능, 적용일 `2026-09-08` |
| 시험 출석 연동 | 사용, 연결 교시 `아침모의고사`, 활성 |

출석 가져오기는 자동 상벌점의 `morningWeekdays`를 사용한다. 교시 관리 요일만 목요일로 체크해도 시험 대상 날짜가 되지 않는다. 동일 날짜 설정 사본에서 목요일만 추가하면 resolver가 정상 교시를 반환했다. **사본은 메모리에서만 변경했고 DB에는 저장하지 않았다.**

설정 변경이 필요한 경우 경로: `/police/admin/settings/rules` → 기준·상벌점 → 자동 상벌점 → 아침모의고사 요일. 목요일 누적시험을 시험 대상에 포함하려면 목요일을 선택하고 적용일을 실제 적용 시작일로 정해야 한다. 다른 목요일의 미응시·개근 계산에도 영향을 줄 수 있으므로 운영자 결정 없이 자동 활성화하지 않는다.

## 2. 첨부 파일의 별도 오류

사용자 첨부:

- `문항분석표-2026-10-01-18-45-47.xls` (26,624 bytes)

- Score: Excel 2·3행에 수험번호가 비어 있고 각 7개의 값이 있음.

- 수험번호 없는 응답의 신원을 원본 채점 프로그램에서 확인·정정 후 다시 내보내는 것이 필요하다. 가져오기에서 제외하는 정책을 구현한다면 제외 건수 안내·원본 유지·대상 학생 미추정 계약을 먼저 정해야 한다.

## 4. 추가 질문: 이전 목요일 채점 및 75문항

사용자는 이전 목요일에도 누적시험을 채점했고 오늘은 75문항이라고 설명했다. 채점 경험을 부정하거나 문항 수를 오류 원인으로 추정하지 않고 추가 확인했다.

- 문항분석표 실제 문항: 헌법 25 + 형법 25 + 형사소송법 25 = **75**. 반복 헤더는 문항으로 세지 않는다.
- Errata 헤더에는 40/40/60/40/60의 240개 답안 자리(과목별 최대 칸)가 있지만 실제 75개 응답이 채워진 식별 가능 블록은 178개다. 여분 헤더 칸이 곧 실제 시험 문항 수를 뜻하지 않는다.
- 진단 중 원본을 메모리에 읽어 수험번호 누락 2개 블록만 제외한 사본을 만들면 기존 파서는 **192개 식별 가능 블록을 모두 읽고 응답 존재를 확인**한다. 파일·운영 DB·제품 코드에 저장하지 않았다. 이 검사는 누락 블록을 자동 제외하는 정책을 승인하거나 구현한 것이 아니다.
- 가져오기 파서는 특정 문항 수(예: 20개)를 강제하지 않는다. 따라서 **75문항은 화면의 교시 없음 오류나 첨부의 수험번호 오류 원인이 아니다.**

이전 목요일의 스터디홀 저장 상태를 기존 운영 연결 DB에서 READ ONLY로 조회했다. 학생 개인정보 대신 집계만 출력했다.

적용 이력 3건의 변경 전후에서도 목요일은 시험 요일에 포함되지 않았다. 조회 대상에 저장 기록이 없다는 사실만으로 채점 프로그램에서 채점하지 않았다고 말할 수 없다. 과거에 사용한 화면/파일/시험일을 확인하지 않아, 채점 프로그램에서만 처리했는지 다른 화면·날짜·환경에 저장했는지는 미확인이다.

## 5. 추가 질문: 누적 성적이 반영된 적이 있는가

경찰 학원의 전체 기간 성적/시험 session/과목 설정/누적 자동 출석을 READ ONLY로 확인했다. 스크립트: `.local/cumulative-grade-history-all-20261001.ts`.

- 시험 종류: 아침 모의고사(MORNING), 정기 모의고사(REGULAR).
- 아침의 `누적모의고사` 과목은 **비활성**. 해당 과목 성적 0건, 누적 이름의 시험 종류에 속한 아침 성적 0건.
- 시험 진도(topic) 또는 원본 이름에 ‘누적’이 있는 session 0건. 일반 성적 JSON에 누적 과목 이름/ID로 저장된 점수도 0건.
- 정기/일반 성적 행은 전체 0건.
- 아침 단과 성적 행은 총 341건(형소법81, 경찰학53, 형법74, 헌법133; 실제 점수는 헌법의 null 2건을 제외한 339건). 가져오기 session은 총 12회(3/2/3/4회). 날짜 범위는 성적 행 기준 9/8~9/30.
- `examAutoSource=MORNING_CUMULATIVE` 출결은 전체 기간 0건.

**현재 남아 있는 이력에서 누적시험 성적 또는 누적 응시 가져오기 성공 기록은 발견되지 않았다.** 이 조회는 원본 채점 프로그램의 실행 이력이나 과거 삭제된 DB 기록까지 입증하지 않는다. 다른 시험/과목명으로 잘못 저장했을 가능성을 임의로 배제하지 않되, 현재 session들의 연결 과목은 모두 위 4개 단과다.

현재 ‘누적시험 응시 여부 가져오기’는 의도적으로 점수·석차·문항 분석을 저장하지 않는다. 누적 성적 반영을 기대하는 사용자 업무와 이 화면의 목적이 다르므로 후속 작업에서 요구 범위를 먼저 확인해야 한다. 이 조사는 누적 성적 기능 개발·활성화 승인이 아니다.

## 6. 사용자 목적 재확정 및 오늘 저장 상태

사용자가 “누적은 성적 반영이 아니고 출석만 반영하면 됨”이라고 재확정했다. 따라서 5절의 요구 범위 미확인은 해소됐으며, 누적 성적 기능을 추가할 이유가 없다.

`.local/today-cumulative-status-20261001.ts`로 경찰 학원의 10/1 아침모의고사 교시를 READ ONLY 재조회했다. 교시는 활성이고 상태/출처별 출결 집계는 빈 배열, **전체 저장 0건**이다. 누적 자동 반영뿐 아니라 해당 교시의 수동 출결도 조회 시점에는 없다. 현재 오늘 출석이 반영됐다고 보고하면 안 된다. 이 조회에서 원장·설정 변경은 수행하지 않았다.

## 7. 승인 후 수정 및 운영 반영 완료 (2026-10-01)

사용자가 오늘 파일 출석 반영을 명시적으로 요청했다. 원본 xls를 수정하지 않고 실제 importCumulativeAttendance 서비스의 미리보기 토큰과 선택 검증을 통해 확정했다. 직접 SQL 상태 덮어쓰기를 하지 않았다.

- 누적 출석 전용 cumulativeAttendancePeriod는 관리규정 아침 교시 요일을 사용한다. 성적 자동화 요일 resolver는 그대로 유지한다. 시작일/휴강일/적용일/연동 사용/학원 소유권 검사는 유지.
- 수험번호 없는 Score 행 및 대응 Errata 정상 블록은 제외 건수를 안내한다. 식별자 비정상/중복/블록 불일치는 오류를 유지한다. 75문항 답안 검증 포함.
- 파일 식별 가능 192명, 학원 일치 응시 27명, 불일치 165명, 식별번호 누락 2건 제외. 학원 28명 중 파일에 없는 노예빈 1명은 미처리 유지.
- 운영 10/1 아침 교시 27건 PRESENT/MORNING_CUMULATIVE 저장. 실제 운영 브라우저에서 아침 교시 select 28개를 읽어 응시 27개/미처리 1개 확인.
- 성적/시험 회차/설정/다른 교시 출결은 백업과 비교해 불변. 파생 계산 재시도 후 경고 0건. 상벌점 원장도 60건이며 내용 불변.
- CLI 실행에는 Next 요청 캐시가 없어 최초 파생 개근 계산이 경고를 반환했다. CLI에서만 캐시 래퍼를 실제 함수 직접 호출로 연결한 뒤 동일한 syncAttendanceDerivedPoints를 재실행해 경고 없는 완료를 확인했다. 사업 로직을 대체하지 않았으며 운영 웹의 캐시 API는 변경하지 않았다. 운영 화면은 새 요청으로 검증했다.
- 관련 단위 10/10 및 typecheck 통과. 전체 955 중 954 통과. attendance-ui-reason-display의 학생 상세 테스트 1건은 단독 실행에서도 실패: 9월 고정 자료를 쓰지만 StudentDetailTabs 초기 이력 필터는 현재 월(10월)이다. 이번 가져오기 코드 경로와 별도이며 해당 테스트 수정은 미실시.
