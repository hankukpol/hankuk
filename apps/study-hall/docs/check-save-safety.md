# 출석·휴대폰 체크 저장 안전장치

2026-09-14. 출석은 수동 저장, 휴대폰은 기존 선택 즉시 자동 저장을 유지한다.

## 적용 범위

- 관리자 출석부(PC·모바일), 조교 출석 체크: 변경한 학생·교시만 저장한다.
- 관리자·조교 휴대폰 체크: 상태 선택과 대여 메모의 포커스 이탈 시 자동 저장한다. 실패한 입력은 저장 버튼으로 재시도한다.
- 메뉴 링크, 로그아웃, 뒤로가기, 날짜·교시 전환, 휴대폰 새로고침 및 이력 탭 전환에서 미저장 여부를 확인한다.
- 저장 처리 중에는 이동·폐기를 막는다. 실패하면 입력과 오류 표시를 유지하며, 완료 후에만 이동할 수 있다.
- 자동 교시 전환은 미저장 입력이나 진행 중인 저장이 있을 때 중지한다.
- 출석 입력을 시작한 뒤에는 화면 크기 변경으로 다른 출석 폼을 다시 생성하지 않는다. 저장 후에도 초기 서버 props로 돌아가지 않는다.

## 저장 실패와 복구

- 출석 전체 저장은 교시별 성공을 따로 반영한다. 중간 실패 시 성공한 교시는 재전송하지 않는다.
- 요청 이후 추가한 입력은 서버 응답으로 덮어쓰지 않는다. 추가 변경은 다시 저장해야 한다.
- 휴대폰 요청은 순서대로 보낸다. 응답의 셀별 세대를 확인해 최신 메모·체크를 보존한다.
- 조회 실패 시 화면 날짜를 마지막으로 불러온 데이터와 일치시킨다. 저장 응답을 기다리는 동안 다른 날짜를 불러오지 않는다.
- 계정·직렬·날짜·교시·탭으로 구분한 변경 셀을 브라우저에 임시 보관한다. 서버에 추가로 자동 저장하지 않는다.
- 24시간 이내의 임시 입력을 같은 계정에서 복구할 수 있다. 서버 기록이 이미 바뀐 셀은 복구에서 제외하고 개수를 안내한다. 서버에 이미 반영된 셀도 재저장 대상으로 만들지 않는다.
- 명시적으로 임시 입력을 버리거나 복구한 사본은 소비한다. 다른 탭에서 더 새로 작성한 사본은 지우지 않는다.
- 새로고침·닫기 경고는 브라우저의 beforeunload 기능을 이용한다. 모바일 강제 종료에서는 이 이벤트가 발생하지 않을 수 있어 임시 보관을 함께 사용한다. 브라우저 저장소 차단·삭제 상황까지 복구를 보장하지 않으며, 보관 실패 시 화면에 안내한다.

## 검증

`tests/check-safety.test.ts`: 실 React/JSDOM으로 링크·뒤로가기·날짜/교시·이력 탭·저장 중 이동 금지, 복구/계정 분리, 추가 입력 보존, 부분 실패와 재시도, 휴대폰 요청 순서·메모 보존을 검증한다.

`tests/phone-date-safety.test.ts`: GET 네트워크/HTTP/JSON 오류, POST 본문 지연, 실패 입력의 명시적 폐기 및 날짜별 저장 대상을 검증한다.

Docker 목업의 실제 Chrome 390×844 및 1280×900 화면에서 관리자·조교의 수동 출석 저장, 휴대폰 자동 저장, 교시/메뉴/뒤로가기/로그아웃 경고, 탭 종료 후 복구, 크기 변경 후 입력 유지, 메모 저장 중 이력 전환 차단을 확인했다. 운영 DB의 출석 기록을 수정하는 QA는 하지 않는다.
