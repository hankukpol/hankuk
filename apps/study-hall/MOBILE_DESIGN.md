# 모바일 디자인 정석 — 벤치마크와 규격

기준일: 2026-09-09
대상: `apps/study-hall` 의 **768px 미만** 화면 전부 (관리자 · 조교 · 학생 포털)
관계: [`DESIGN.md`](DESIGN.md) 가 토큰·클래스·데스크톱 규격의 원본이다. 이 문서는 **모바일에서 그 규격을 어떻게 배치하는가**를 정한다. 두 문서가 충돌하면 토큰·색·글자 하한·터치 규격은 DESIGN.md 를, 모바일 배치는 이 문서를 따른다.

---

## 0. 왜 이 문서가 필요한가

사용자 판정: 현재 모바일 화면은 **"AI 가 만든 것처럼 보인다"** — 억지 카드 도형으로 감싸고, 카드를 1행씩 세로로 나열한 전형적인 형태. 사람이 만든 한국 교육 사이트 모바일처럼 바꾼다.

참고 사이트로 **공단기(gong.conects.com) 모바일**을 지정받았다. 375×812 뷰포트로 접속하면 별도 모바일 페이지(`/view_m/` 등)가 내려오며, 아래 수치는 전부 그 모바일 페이지를 `getComputedStyle` 로 실측한 것이다. 스크린샷 인상이 아니라 숫자다.

## 2. 스터디홀 모바일 규격 (768px 미만) — 이것이 정석이다

DESIGN.md 의 **불변 조항은 그대로다**: 13px 미만 글자 금지(§3), 터치 대상 44px(§8), 토큰 밖 색 금지(§2), 그림자 금지(§7), 카드 안 카드 금지(§5.2). 공단기가 11~12px 을 써도 우리는 13px 이 하한이다. 그 안에서 공단기의 **배치**를 가져온다.

### 2.1 상단 크롬 — 51px 한 줄로

- 768px 미만에서 페이지 제목은 **본문이 아니라 헤더 바 안**에 둔다. `이전(←) · 제목 · 우측 액션` 한 줄, 높이 **52px**(터치 44 + 여유), sticky, `surface` 배경, 하단 1px `line-soft`.
- 제목은 **16px/700 가운데**. 두 줄이 되면 말줄임이 아니라 **줄바꿈**(§3 "제목을 truncate 하지 않는다") — 그때는 바 높이가 늘어난다.
- 우측 액션은 **텍스트 15px/600** 최대 2개. 아이콘 버튼은 44×44.
  - 실측 결과 이 제한을 넘는 화면은 **수납 하나뿐**(5개: 새로고침 · 신규 등록 · 연장 · 환불 · 일반). 뒤의 넷은 전부 "수납 등록"의 유형 분기이므로 헤더에는 `수납 등록` 하나만 두고 유형은 등록 화면 안에서 고른다. 서비스는 바뀌지 않는다. 나머지 화면은 0~2개로 이미 맞는다.
- `.admin-page-description` 은 768px 미만에서 **숨긴다.** 설명이 꼭 필요하면 첫 섹션 상단에 13px `admin-help` 로 한 줄.
- `.admin-utility-row`(앱 전환·채팅)는 768px 미만에서 헤더 바 우측 액션으로 합친다. 별도 44+24px 행을 두지 않는다.
- 검은 상단 헤더(§5.1 `admin-mobile-header` 64px)는 **홈 화면에만** 남긴다. 서브 화면은 위 52px 바가 헤더다. 메뉴 서랍은 바 왼쪽 `≡` 로 연다.

**합격 기준**: 서브 화면에서 첫 데이터(표 첫 행·목록 첫 항목)의 top ≤ **160px** (52 헤더 + 43 탭 + 20 여백 + 제목 없음). 홈은 ≤ 240px.

### 2.2 탭

- **1차 탭(§5.4 폴더 탭)은 768px 미만에서 폴더 모양을 버린다.** 가로 스크롤 텍스트 탭 **44px**, 15px/600, gap 12, 좌측 시작 16px, `flex: 0 0 auto`(자연 폭). 활성 = `text` 700 + **아래 2px accent 막대**(우리 §5.5 와 동일), 비활성 = `text-muted` 600. 배경·테두리 없음.
- 2차 탭은 §5.5 그대로(밑줄형)이되 모바일에서 **43px**, 14px/700 로 한 단계 줄인다. 활성 accent + 2px 밑줄, 비활성 muted.
- 두 줄로 접히는 탭은 없다. 넘치면 **가로 스크롤**이고 활성 탭을 화면 안으로 스크롤한다(현행 `AdminTabs scrollable`).
- 768px 이상은 §5.4·§5.5 그대로.

### 2.3 조건 선택 — 칩

- 768px 미만에서 `.admin-choice-button`(128px 고정폭 44px 8px)은 **칩**이 된다: 높이 **36px**(44 는 칩에 과함, 대신 세로 padding 으로 터치 44 확보), radius **999px**, 13px/600, 좌우 padding 12, 1px `line`, `surface` 배경. 활성 = **`text` 배경 + `surface` 글자**(공단기 검정 반전). 직렬 accent 는 쓰지 않는다 — 검정이 어디서나 같은 뜻이다.
- 칩 행은 가로 스크롤, gap 8, 좌측 시작 16. 줄바꿈하지 않는다.
- 폼 안의 조건(날짜·기간)은 §5.7 입력 그대로 44px.
- **`.admin-status-button`(표 안 출결 지정)은 칩이 되지 않는다.** §8 이 그 버튼을 "테두리 상자로 감싸지 않고 2px 밑줄로 표시" 라고 이미 정했고, 알약 칩은 그 반대(테두리 있는 상자)다. 표 셀 안의 상태 지정은 §8 규격을 그대로 둔다. 칩은 **표 밖의 조회 조건**에만 쓴다.

### 2.4 목록 — 행이지 카드가 아니다

- **§5.3 "768px 미만은 기록 카드" 규칙을 폐기한다.** 상벌점·수납·외출·공지·면담·성적 모두 **구분선 행**이다.
- 단순 행: **48px**, 좌우 16px, 1px `line-soft` 하단선, 좌 제목 15px/400 · 우 값 15px/600 `tabular-nums`, 이동 가능하면 우측 `›` 20px muted.
- 복합 행(제목+메타): padding **16px 16px**, 위 라벨 13px/600 `text-muted` → 제목 15px/400 최대 2줄 → 메타 13px `text-muted`. 높이는 내용이 정한다(대략 96~130px).
- **라벨 자리는 `분류 + 날짜`다.** 상벌점 `categoryLabel + date`, 수납 `paymentTypeName + paymentDate`, 면담 `resultType + date`, 성적 `examTypeName + examDate` 가 이미 그 형태다. 날짜가 없을 수 있는 목록(성적의 `examDate`)은 대체 문구를 정해 둔다.
  - **공지에는 분류 축이 없다.** 있는 것은 `scope`·`isPinned`·`isPublished` 로 전부 상태값이다. `scope`(전체/지점)를 분류로 쓰고 `publishedAt` 을 날짜로 둔다 — 읽는 사람에게 "전체 공지"와 "경찰반 공지"는 실제로 다른 종류다. **새 분류 컬럼을 만들지 않는다.**
- 상태값은 §8 그대로 **상자 없이 색 글자**. 배지는 라벨 자리에만.
- 행 하나에 버튼을 두 개 이상 세우지 않는다. 행 작업은 우측 `›` 로 들어간 상세에서 한다.
- 첫 행 위·마지막 행 아래에 선을 긋지 않는다(카드처럼 닫히지 않게).
- **`.admin-choice-card`(여러 줄 선택 카드)도 768px 미만에서는 행이다.** 목록이 아니라 선택 컨트롤이지만, 전체 폭 카드가 세로로 쌓이면 §0 이 지적한 "카드 1행 나열" 그대로가 된다. 테두리·모서리를 버리고 1px `line-soft` 구분 행이 되며, 선택은 **`accent-soft` 배경 + 왼쪽 3px accent 막대**로 표시한다(§5.1 사이드바 활성 표시와 같은 방식). 제목 15px/600, 보조 13px muted. 768px 이상은 §5.6 카드 그대로.

### 2.5 요약·지표 — 상자를 없앤다

- 768px 미만에서 `.admin-dashboard-metric`(테두리 카드)과 `.admin-metric-box` 는 **`.admin-portal-summary` 방식**(1px 간격에 `line-soft` 가 비치는 격자, 사방 선)으로 통일한다. 학생 포털이 이미 이렇게 한다 — 관리자·조교 대시보드도 같게.
- 2열 기본, 항목 3개면 3열. 라벨 13px/600 muted 위, 값 **20px/700** 아래. KPI 32px 은 768px 미만에서 쓰지 않는다(§5.3 도 "32px 넷이면 한 화면을 다 쓴다"고 이미 경고한다).
- 지표 4개 이하면 격자 대신 **한 줄 텍스트 요약**도 허용. 15px/600, 구분 ` · `.
- **요약에 쓰는 값은 화면에서 계산하지 않는다.** 서비스가 완성된 값을 준다. 계산이 화면에 있으면 관리자 화면과 학생 화면이 같은 학생에게 다른 숫자를 보여줄 수 있다.
- **그래서 계산이 필요 없는 값만 고른다.** 아래 다섯은 전부 이미 서비스가 주는 값이라 서비스 작업이 없다.

| 화면 | 문구 | 출처 |
| --- | --- | --- |
| 성적 | `응시 12회 · 최신 총점 205점 · 반 3등` | `regularExams.length` · `[0].totalScore` · `[0].rankInClass` |
| 상벌점 | `상점 12점 · 벌점 3점 · 순합계 9점` | `student.meritPoints` · `demeritPoints` · `netPoints` |
| 출결 | 기존 값 | `getStudentDashboard` 의 `monthlyAttendanceRate` · `attendedCount` · `expectedCount` |
| 휴가 | 기존 값 | `previewLeaveSettlement` 의 `holidayRemaining` 등 |

- **평균 점수와 총 회차는 쓰지 않는다.** 평균은 "점수가 없는 회차를 분모에 넣는가"라는 판단을 요구하고, 그 판단이 어디에 있든 두 화면이 갈릴 여지를 만든다. 위 조합으로 요약이 성립하므로 그 문제를 아예 만들지 않는다. 평균이 정말 필요해지는 화면이 나오면 그때 서비스에 넣는다.

### 2.6 표

- §5.8 그대로. 모바일 추가 규칙: 표는 `.admin-table-frame` 안에서 **가로 스크롤**하고 문서는 넘치지 않는다(공단기 209px 넘침이 프레임 안에 갇힌 것과 같다).
- 첫 열(이름·날짜)은 `.admin-table-sticky-col` 로 고정.
- 셀 13px, padding **10px 8px**(데스크톱보다 좁게), 머리글 `accent-tint` 유지(공단기 회색 머리글은 토큰 밖이라 안 가져온다).

### 2.7 버튼·모서리

- 768px 미만 컨트롤 모서리는 **4px** (`--admin-radius-mobile: 4px` 신설, 버튼·입력·select·textarea·안내 상자). 8px 은 이미지·배너·모달에만. 칩·알약은 999px. 목록·표·탭·헤더는 0.
- 전체폭 실행 버튼 **48px**, 15px/600. 페이지 하단 실행은 sticky 바가 아니라 콘텐츠 끝에 둔다(공단기와 같다). 단, 조교 출석체크처럼 **저장이 반복되는 화면**은 §8 대로 하단 sticky 저장 바를 유지한다.
- 보조 실행은 `.admin-text-action`(§5.6) 15px/600, 상자 없음.

### 2.8 간격

| | 값 |
| --- | --- |
| 좌우 여백 | 16px |
| 섹션 상단 padding | 20px |
| 섹션 제목 → 첫 콘텐츠 | 16px (표·목록 바로 아래는 12px) |

### 2.9 색·글자 — 바꾸지 않는 것

- 토큰은 DESIGN.md §2·§3 그대로. 공단기 `#7e8b9a` 는 우리 `text-muted`, `#ededf3` 는 `line-soft`, `#121212` 는 `text` 에 대응한다. 새 색을 만들지 않는다.
- 글자 크기 사다리(모바일): **16 제목 · 15 본문/행 · 13 메타/표/라벨**. 12·11 은 쓰지 않는다.
- 굵기 400/600/700 세 단계(§3).

## 3. 세 역할 공통 포맷

관리자·조교·학생이 **같은 포맷**을 쓴다. 역할별로 다른 것은 메뉴 항목과 데이터뿐이다.

```
[52px 헤더 바]  ≡ 또는 ←   제목(16/700 가운데)   액션(15/600)
[44px 1차 탭]  가로 스크롤 텍스트 탭 (있는 화면만)
[43px 2차 탭]  밑줄형 (있는 화면만)
[36px 칩 행]   조건 선택 (있는 화면만)
[20px]
[요약 격자]    선으로만 나눈 2~3열, 값 20/700 (있는 화면만)
[20px]
[섹션 제목 16/700]  ·  우측 텍스트 액션
[16px]
[목록 행 48px ×n  또는  표 프레임(가로 스크롤)]
[20px]
…
[32px 하단 여백]
```

- **홈(대시보드)** 만 검은 64px 헤더 + 요약 격자 + 바로가기 행 목록. 나머지는 위 포맷.
- 조교 출석체크·휴대폰 체크: 위 포맷 + 하단 sticky 저장 바(§8).
- 학생 포털: 1차 탭이 화면 이동(§8) — 위 포맷의 1차 탭 자리에 온다.

## 5. 적용 순서

**1단계와 1.5단계를 나눈 이유.** 제목을 헤더 바로 옮기는 것과 유틸리티 행을 흡수하는 것은 **마크업이 있어야 한다**. CSS 로는 숨기는 것까지만 되므로, 한 단계로 묶으면 중간 커밋에서 모바일 제목이 사라지고 앱 전환·채팅에 못 들어간다. 그래서 "숨기는 규칙"은 "옮기는 마크업"과 같은 커밋에 둔다.

1. **CSS 만** (`globals.css` + `DESIGN.md`, 한 커밋) — `--admin-radius-mobile`, 1차 탭 텍스트 변형, 2차 탭 43px, 칩, 목록 행 클래스, 요약 격자 공용화, 간격, 표 셀 padding, `.admin-page-description` 숨김, `.admin-mobile-topbar` **규격만**(적용은 다음 단계).
2. **마크업** (`AdminShell` · `StudentPortalFrame` · assistant layout) — 헤더 바를 실제로 붙이고 제목을 그 안으로, 유틸리티 행을 우측 액션으로 흡수. **`.admin-page-title` 본문 숨김과 `.admin-utility-row` 숨김을 이 커밋에 함께 넣는다.**
3. 홈 3개(관리자 대시보드·조교 홈·학생 첫 화면) → 포맷 확정.
3. 목록 화면(출결·상벌점·수납·면담·공지·성적) → 카드→행.
4. 조교 출석체크·휴대폰 체크 → 크롬 압축 + 칩.
5. 나머지 설정·상세.
6. 각 단계 끝에 §4 검증.

이 문서를 바꿀 때는 실측 근거를 같이 적는다. "보기 좋아서"는 근거가 아니다.
