# 수업 일괄 해제: 로컬 구현·검증

2026-10-02, 기준 HEAD `4bb19a9`. 사용자 요청은 로컬 구현과 테스트다. 앞선 운영 학생 1명 정정과 이번 기능 구현은 별개다.

## 사용법과 동작

출석 관리 → 학생 이름 → **수업 해제** → 학생 여러 명·기간·요일·시작/종료 교시 → **해제 대상 확인** → 해제/보존 건수 확인 → **수업 해제 확정**.

- 기존 좌석 배정 학생 선택, 최대120일·10,000칸 검증을 공유한다. `isClassAttendance`로 판정한 수업만 미처리(출결 행 없음)로 변경한다.
- 출석·지각·결석·일반 사유·휴무·반휴와 시험 자동 출처가 있는 행은 보존한다. 미리보기는 무변경이며 범위/원장 변경 시 다시 확인한다. PostgreSQL에서는 Serializable 트랜잭션으로 검사와 삭제를 수행한다.
- 과거/오늘 정정의 파생 계산은 기존 서비스를 호출하되 시험 출결 재작성은 하지 않는다. 미래 점수는 계산하지 않는다. 실패는 저장 여부와 구분해 안내하며, 재확인 후 빈 대상 재시도로도 계산을 복구할 수 있다.
- 일반 반복 입력의 저장 불가능한 ‘미처리’ 옵션은 숨겼다. 시작일을 변경해도 선택한 요일을 유지한다.

## 파일

`AdminAttendanceBoard.tsx`의 기존 SlideOver·선택 버튼·안내·하단 버튼을 재사용했다. `/api/[division]/attendance/recurring`에 operation/preview/previewToken을 추가했고 기존 인증·기능 검사를 유지했다. `attendance.service.ts`가 범위 검증·캐시 갱신·파생 계산을 담당하고 신규 `class-attendance-release.service.ts`가 mock/DB의 미리보기·삭제를 담당한다. 신규 `tests/class-attendance-release.test.ts`에서 보존·충돌·재시도를 검증한다.
