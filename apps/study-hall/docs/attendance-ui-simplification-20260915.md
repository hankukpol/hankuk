# 출결 화면 기능 정리 — 로컬 검증

확인일: 2026-09-15. 사용자 요청에 따라 기존 디자인 컴포넌트를 유지하며 불필요한 입력 흐름을 제거했다.

## 변경

- 관리자 출석부와 관리자 모바일·조교 출석체크에서 `도착 시각 기록` 버튼과 입력창을 제거했다.
- 교시 설정의 `선택자습 신청` 탭·신청 폼을 제거했다. 교시 목록이 바로 표시되며, 이전 `#optional-study` 주소로 열어도 목록을 표시한다.
- 관리규정의 `신청 학생` 선택 옵션과 수동 도착 시각 판정 설정을 제거했다. 학생 관리규정에서도 신청 안내를 제거했다.
- 과거 개별 대상 설정은 읽기 표시와 원본 데이터로 보존한다. 기존 계산 규칙과 교시별 출결 원장은 변경하지 않는다.
- 이전 화면의 `enroll` / `end-enrollment` 요청은 권한 검사 후 HTTP 410으로 거절한다. 같은 API의 교시 출결 벌점 확정 동작은 유지한다.
- 기존 대상 기록 보호 오류에서 삭제된 신청 화면으로 이동하라는 안내를 제거했다.

## 유지

- `/[division]/check-in`: 학생 수험번호 입력으로 하루 최초 등원 시각 기록.
- `/[division]/admin/arrivals`: 관리자 날짜별 등원 시각 조회.
- `/[division]/student/attendance`: 본인 등원 시각·월간 달력과 기존 교시 출석표.
- 등원 원장·정정 이력, 기존 출결·벌점·성적·휴대폰 및 학원별 설정.

## 검증 결과

- 기준 서버: `http://localhost:3000`, main 소스, `study-hall-dev-1`, 모의 데이터.
- `pnpm exec tsc --noEmit`: 통과.
- 변경 파일 Next lint: 경고·오류 없음.
- 기존 등원·교시 출결·설정 UI 회귀 82개 및 API 회귀 3개: 모두 통과.
- 실제 Chrome에서 관리자 출석부, 교시 설정, 관리규정, 등원 현황, 조교 출석체크, 학생 출석, 공용 등원 페이지를 390·768·1280px로 확인: 21개 화면 조합 통과.
- 이전 신청 API 2개 동작의 HTTP 410 및 조교 권한 거부를 실제 로컬 HTTP로 확인.
- 교시 설정의 수정 버튼, 기본 출석 입력, 학생의 오늘 등원 시각 표시를 확인했다. 설정 폼 조작은 저장하지 않았다.
- 화면 가로 넘침과 브라우저 실행 오류 없음. 기존 공통 글꼴·버튼·표·탭 디자인을 유지한다.
- 공용 기기는 미등록 상태 화면으로 확인했다. 신규 기기 등록이나 실제 등원 접수는 만들지 않았으며, 수험번호·중복 입력·최초 시각 보존은 격리된 회귀 테스트로 확인했다.
- 개발 서버 HMR 모듈 오류는 담당 작업에서 같은 컨테이너만 재시작한 뒤 해소되었고, 그 이후 모든 브라우저 검증이 통과했다.

검증 스크립트와 화면: `.local/attendance-ui-removal-qa.cjs`, `.local/attendance-ui-removal-qa/results.json`, 같은 폴더의 PNG.

로컬 확인과 운영 배포는 별개다. 이 작업에서 학원 설정·운영 기록 변경, DB 마이그레이션, Git 커밋·푸시, 배포를 실행하지 않았다.
