# 누적모의고사 응시 여부 가져오기 검증

검증일: 2026-09-18 (Asia/Seoul)

## 반영 범위

- 출석 관리 → 누적시험 응시 여부 가져오기. 아침모의고사 성적 가져오기 화면에도 진입 링크를 제공한다.
- 채점표의 수험번호와 실제 선택 답안 유무만 읽어 기존 재원생과 연결한다. 점수, 석차, 문항 정답·오답, 문항 통계는 저장하지 않는다.
- 답안이 확인되면 응시 후보로 표시한다. 빈 답안 또는 파일에 없는 학생은 기본적으로 반영하지 않으며, 관리자가 응시·미응시를 확인해 선택한다.
- 기존 응시·지각·승인 사유·휴강 등의 기록은 보호한다. 미응시 기록을 응시로 고칠 때도 관리자 선택이 필요하다.
- 해당 날짜에 유효한 학원별 아침모의고사 교시·시행일·요일·휴강 설정을 사용한다. 기존 설정에 따른 출석 파생 상벌점은 재계산하되 성적·석차 자료를 만들지 않는다.
- 저장 후 실제 시험일 출석부로 이동할 수 있다.

## 원본 파일 읽기 확인

사용자가 제공한 2026-09-18 내보내기 파일 두 개를 로컬에서 읽었다. 분석표 안의 실제 시험일은 **2026-08-20**이며, 채점표의 87명 모두 선택 답안이 확인됐다. 추출 학생 필드는 `studentNumber`, `hasAnswer`뿐이다.

이 확인은 읽기 전용이며, 실제 87명의 출석을 운영 DB나 목업 DB에 저장하지 않았다. 브라우저 저장 검증에는 별도의 가상 학생과 합성 XLS를 사용했다.

HTTP 검증은 인증 실패, 타 학원 접근, 외부 출처 요청, 시험일 불일치, 다른 학생 ID, 승인 기록 덮어쓰기, 변경된 미리보기 재사용을 거부하는지 확인했다. 선택한 학생 3명의 응시·미응시가 저장 후 재조회에서 유지됐고, 모든 성적·시험·문항·답안 데이터와 다른 학원 출석은 변경되지 않았다.

회귀 검증에는 월중 아침 교시 변경, 정책 비활성 날짜, 한국 시간 기준 입반일, 자동 응시 기록 삭제 후 최신 출석을 기준으로 상벌점 재계산하는 경우를 포함했다.

## 브라우저 검증

- 별도 목업 서버: `http://localhost:7630`
- PC 1280×900, 태블릿 768×1024, 모바일 390×844에서 확인했다.
- PC는 표, 모바일은 학생별 2열 구조로 표시되며 화면·목록의 가로 넘침이 없었다.
- XLS 두 개 선택 → 미리보기 → 누락 학생을 미응시로 직접 선택 → 1명 저장 → 해당 날짜 출석부 이동을 수행했다.
- 출석부에서 응시 2명, 승인 사유 미응시 1명, 직접 확인한 미응시 2명이 표시되는 것을 확인했다. 다른 교시는 미처리 상태를 유지했다.
- 검증 후 임시 뷰포트 설정을 해제하고 가져오기 화면을 열어 두었다.

## 추가 로컬 재리뷰

사용자의 재리뷰 요청에 따라 최신 원본과 격리 서버의 파일 해시가 같은지 확인한 후 자동 테스트와 브라우저 저장을 다시 실행했다. 아래 두 종류의 문제를 발견해 수정했다.

1. **기존 수동 성적을 응시 근거에서 누락:** 수동 아침성적이 0점이어도 기존 미응시 출석과 함께 있으면 미응시 벌점이 생길 수 있었다. 실제 저장된 유효한 수동 아침성적을 응시 근거로 읽도록 수정했다. null 점수와 다른 학원 시험 종류는 제외하며, 새로운 성적·시험·참여자·석차 기록은 생성하지 않는다. 0점·80점·null 및 출석 동기화 활성·비활성 조합을 회귀 검증했다.
2. **저장 후 조회 문맥 불일치:** 모바일 출석부가 현재 시간대 교시로 이동하고 벌점 확인 날짜가 오늘로 남았다. 저장 결과의 교시 ID를 링크로 전달하고 현재 학원 교시인지 검증한 뒤 선택 상태를 유지한다. 벌점 확인의 초기 날짜도 저장한 시험일과 맞췄다.

수정 후 모바일에서 합성 파일 미리보기 → 누락 학생 1명 미응시 선택 → 저장 → 출석부 이동을 다시 수행했다. 2026-09-14의 0교시가 즉시 선택됐으며 벌점 확인 날짜도 2026-09-14였다. PC 재조회에서 응시 2명·승인 사유 미응시 1명·직접 확인 미응시 2명이 유지됐다. 관찰된 브라우저 오류 로그는 0개였다.

최종 자동 검증은 총 **59개 통과**(44 + 1 + 14)했으며 타입 검사와 변경 범위 lint도 통과했다. 독립 리뷰에서도 수정된 문제 외 남은 문제는 발견하지 못했다. 최종 브라우저는 실제 저장 결과를 볼 수 있는 해당 날짜 출석부에 두었다.

## 독립 코드 리뷰 및 한계

읽기 전용 리뷰에서 지적한 날짜별 교시 선택, 입반일 시간대, 출석 동기화 후 상벌점 계산 자료 갱신을 수정하고 회귀 테스트를 추가했다. 최종 재검토에서 이번 범위의 추가 문제는 발견되지 않았다.

운영 DB 쓰기, 운영 배포, 커밋·푸시는 하지 않았다. 실제 PostgreSQL 통합 실행, 프로덕션 빌드 및 Lighthouse 성능 측정은 이번 검증 범위에 포함하지 않았다.
