## 3. 지켜야 할 기존 결정

- **변경(운영자 지시 2026-09-25, 확정 대기)**: 2026-09-14 확정 규칙 ‘학생 성적은 내용을 숨기지 않는 섹션 바로가기’를 폐기하고 **한 화면에 한 주제**로 나눈다. 운영자 판단: 한 페이지에 정보가 나열되어 찾기 어렵다. 승인되면 DESIGN.md §학생 개인 성적 전용 페이지를 함께 고친다.
- 탭 줄은 두 겹이 되면 안 된다(§5.5). 그래서 **분석 항목을 2차 밑줄 탭**(요약 · 취약점 · 석차 · 추이 · 문항)으로 올리고, **시험 종류(정기·아침)는 조회 조건의 선택 칩**으로 내린다. 1차 학생 메뉴 + 2차 분석 탭, 두 줄뿐이다.
- 학생과 관리자 개인 분석이 **같은 5개 탭**을 쓴다. 같은 이름, 같은 순서라 상담할 때 같은 화면을 가리킬 수 있다.
- 각 탭은 모바일 **2화면 이내**. 요약 탭은 **1화면**에 끝난다. 인쇄는 탭과 상관없이 전체를 출력한다(비활성 탭 DOM 유지, 기존 관리자 규칙과 같음).
- 요약은 테두리 상자가 아니라 `.admin-portal-summary` 선 격자. 표 안 상태는 글자색만. 긴급 경고는 `.admin-notice` 톤 + 읽을 수 있는 문구(§8).
- 과목 선택처럼 표시 대상을 거르는 것은 선택 칩(§학생 개인 성적 전용 페이지).
- **왼쪽 굵은 막대 금지**(§5.8, 운영자 지시 2026-09-25). 그림자·그라데이션 금지(§7).
- 경찰 순서·기준을 코드에 박지 않는다. 과목 순서는 시험 템플릿의 `displayOrder`, 과락 기준은 학원별 설정(CLAUDE.md 학원별 독립 설정 원칙).

## 4. 판정 규칙

### 4.1 과락

- 설정: 운영 규칙 → 성적 분석(`RulesSettingsManager`)의 `과락 기준 (%)`. `examAnalysis.common.failCutoffPercent`(기본 40, 0~100). **0이면 과락을 판정하지 않는다** — 설정 정규화가 숫자 필드만 다루므로 켜기/끄기 필드를 따로 두지 않았다. 저장은 기존 성적 분석 설정 흐름을 그대로 탄다. **구현 완료(9/25).**
- 판정: 과목 점수 < 과목 만점 × 기준% 이면 `과락`. 과목 만점을 알 수 없으면(만점 미보관 입력 성적) `판정 불가`로 표시하고 과락으로 세지 않는다.
- 정기: 응시한 과목만 판정한다. 선택과목 묶음은 고른 과목만. 부분 응시로 빠진 과목은 `미응시`이며 과락이 아니다.
- 아침: 한 과목 시험이므로 같은 기준을 ‘과락선 미만’ 회차로 센다.
- 표시: 과락이면 `과락`(danger), 아니면 **기존 과목 등급 `grade`(우수·보통·취약, `gradeSubject` — 응시자 10명 이상이면 상위 비율, 미만이면 득점률 기준)** 를 그대로 쓴다. 새 등급 기준을 만들지 않는다. 합격 판정이 아님을 문구로 밝힌다.
- 순수 함수 `isBelowFailCutoff`, `subjectVerdict` — `lib/exam-preview/report-summary.ts`. 단위 테스트 `tests/unit/report-summary.test.ts`(경계값 40% 통과, 부동소수 경계, 만점 없음, 기준 0). **구현 완료(9/25).**

### 4.2 한 줄 결론

규칙 기반 문장이다(같은 입력이면 같은 문장). 학생과 관리자가 같은 문장을 본다. 정기는 `regularHeadline()`(`lib/exam-preview/report-summary.ts`) **구현 완료(9/25)**, 아침·관리자 짧은 판은 해당 단계에서 더한다.

정기: 아래 조각을 순서대로 ` · `로 잇는다. 값이 없는 조각은 뺀다.

1. `총점 {내 점수}/{만점}점`
2. `{응시자}명 중 {석차}위(상위 {n}%)` — 시험 전체(가져온 파일 응시자) 기준
3. `과락 {과목, …}` 또는 `과락 없음`
4. `{과목}에서 {n}점을 가장 많이 잃었습니다` — 과목별 (만점 − 내 점수) 최대
5. 할 일 하나 — 쉬운 문제 오답이 있으면 `많이 맞힌 문제 중 틀린 {n}문항부터 다시 보세요`, 없고 반복 오답 진도가 있으면 `{진도} 반복 오답을 복습하세요`, 둘 다 없으면 `틀린 {n}문항을 다시 풀어 보세요`

아침(최근 주 기준): `이번 주 {n}과목 평균 {점수}점(반 평균 {±}) · {과목} {k}회 연속 하락 · 과락선 미만 {m}회 · {할 일}`.

톤: 과락이 있으면 danger, 하락 진단이 있으면 warning, 없으면 기본 `.admin-notice`.

관리자 목록용 짧은 판: `과락 경찰학 · 최대 손실 경찰학 30점 · 쉬운 문제 3개`.

## 5. 학생 — 정기 모의고사 (한 페이지 19섹션 → 탭 5개, 탭당 한 주제)

상단: 1차 학생 메뉴 → **2차 분석 탭**(요약 · 취약점 · 석차 · 추이 · 문항) → 조회 조건 한 줄(시험 종류 칩 `정기 | 아침` · 시험일). 처음 열면 **요약 탭**. 인쇄 버튼은 하나(`인쇄 / PDF`)로 합쳐 조회 조건 줄 오른쪽에 둔다.

요약 탭 안에는 다른 탭으로 가는 길을 둔다: 과목 행을 누르면 그 과목이 선택된 취약점 탭, ‘석차 자세히’는 석차 탭으로 간다. 학생이 탭 이름을 몰라도 요약에서 따라 들어간다.

| 탭 | 담는 것 | 합치거나 빼는 기존 구간 |
|---|---|---|
| **요약** | 한 줄 결론(`.admin-notice`) · 요약 격자 4칸(총점, 석차·상위%, 평균 대비, 목표 또는 상위 30%까지) · **과목별 성적표**(과목 · 점수/만점 · 평균 대비 · 과목 석차 · 판정) | 전과목 종합 분석, 종합 위치, 전과목 성적 비교, 과목별 성적과 위치(헌법 분석·상대 위치), 목표 대비 성적 |
| **취약점** | 과목 선택 칩(전체·과목들) · **복습 우선순위 표 하나**(순위 · 과목·진도 · 잃은 점수 · 이유 · 문항 보기) · 진도 연결이 있을 때만 진도표 4열(진도 · 내 정답률 · 전체 정답률 · 판단). 재풀이·복습 예약은 행에서 `SlideOver`로 연다 | 과목별 학습 우선순위, 진도별 취약점과 다음 학습, 반복 오답과 복습 후 확인, 최근 두 회차 진도 비교(→ 진도표의 `변화` 한 열), 복습할 문항 한눈에 보기, 복습 예약과 재풀이, 학습 점검 |
| **석차** | 요약 격자(내 총점, 바로 위 석차와의 차이, 상위 30% 평균까지, 목표까지) · 앞뒤 5명 표(현행) · 점수 분포(9/25 수정본) | 다음 목표와의 차이 |
| **추이** | 차트 하나(총점·상위%) · 회차 표 하나(시험일 · 총점 · 석차 · 상위% · 과락 과목 · 출처) | 최근 6개월 성적 추이의 표 네 개, **직접 입력 성적**(첫 화면에서 이 표로 옮기고 출처 열로 구분) |
| **문항** | 필터 칩(내 오답 · 우선 복습 · 전체 · 오답률 TOP 5) · 채점표(현행). 풀이시간 입력은 이 탭 끝 접이식 | 과목별 문항 분석, 풀이시간 점검 |

통계 방법 열(비교 문항 수, 비교 회차 수 등)은 표에서 빼서 해당 탭 끝 `판단 기준` 접이식으로 옮긴다. 계산은 그대로다.

## 6. 학생 — 아침 모의고사 (주간 단위)

학원 운영이 주 단위(헌법 → 형소법 → 형법 → 누적 → 경찰학)이므로 화면도 주 단위로 짠다.

- **기본 기간: 최근 8주**(오늘 하루 폐기). 과목별 최소 4회(`movingAverageSessions`) 기준으로 과목당 약 8회가 잡혀 추세·진단이 나온다. 기존 ‘오늘 · 이번 주 · 이번 달’ 바로가기는 ‘최근 4주 · 8주 · 12주’로 바꾼다(최대 92일 제한 유지).
- 과목 탭을 첫 선택 단위로 두지 않는다. 주간표가 모든 과목을 한 번에 보여 주므로 ‘첫 과목이라 빈 화면’이 생기지 않는다.

정기와 같은 5개 탭을 쓴다. 탭별로 담는 것만 다르다.

| 탭 | 담는 것 |
|---|---|
| **요약** | 한 줄 결론 · 아래 주간 성적표 |
| (요약 안) **주간 성적표** | 행 = 주차(최근이 위), 열 = 시험 템플릿 과목 순서(`displayOrder`). 셀 = 점수, 과락선 미만은 danger 글자. 마지막 행 = 과목별 기간 평균과 반 평균 대비. 모바일에서는 DESIGN §8 주간 출석표처럼 행·열을 뒤집는다(과목 행 × 최근 4주 열) |
| **추이** | 과목 · 최근 평균 · 반 평균 대비 · 추세(기존 하락 진단) · 응시율 |
| **취약점** | 정기와 같은 복습 우선순위 표(진도 = 가져올 때 입력한 회차 진도) |
| **문항** | 시험일별 채점표 |
| **석차** | 주간 석차 변화(기존 `weeklyRankings`) |

- **누적**은 점수를 가져오지 않고 출석만 반영한다(`ExamImportWizard`). 주간표의 누적 열은 점수 대신 `응시/결시`를 보여 준다. 이 값은 분석 source 에 없는 출결 기록(누적 가져오기로 만든 출석)에서 읽어야 하므로 2단계에서 연결한다. 연결 전에는 `출석만 반영` 머리글 안내만 둔다.
- 과목 순서는 코드에 두지 않는다. 운영 police 아침 설정 순서는 9/25 읽기 전용 조회 결과 헌법·형법·형사소송법·경찰학·누적으로 실제 순서와 다르다. 시험 템플릿 편집에 과목 위로·아래로 버튼을 추가했으므로(9/25) 배포 후 운영자가 헌법 → 형사소송법 → 형법 → 누적모의고사 → 경찰학으로 바꾼다.

## 7. 관리자

### 7.1 반 분석 — 학생별 취약점 표 (새로 추가)

한 표에서 누가 어느 과목이 약한지 본다. 데이터는 기존 `RegularCohortAnalysis.ranking`(학생별 과목 점수·석차·진단)과 과목 만점으로 충분하다.

| 열 | 내용 |
|---|---|
| 학생 | 이름·수험번호 |
| 총점 · 석차 | |
| 과목별 칸(과목 수만큼) | 점수, 판정 글자색(과락·취약) |
| 한 줄 요약 | §4.2 관리자용 짧은 판 |
| 개인 분석 | 링크 |

- 기본 정렬은 **위험 순**: 과락 과목 수 → 하락 진단 → 취약 과목 수 → 석차.
- 필터 칩: 전체 · 과락 · 하락 · 취약.
- 표 위 반 요약 격자: 응시 인원, 반 평균, 과락 학생 수, 과목별 과락 학생 수.
- 기존 ‘학생별 분석 이동’ 표를 이 표로 대체한다. 반 전체 많이 틀린 문항(`classWrongTop`)은 유지한다.
- 아침은 같은 모양으로 행 = 학생, 열 = 과목(선택 기간 평균), 칸 글자색 = 과락선 미만 회차 유무, 추세 열 추가.

### 7.2 학생 개인 분석

학생 화면과 같은 5개 항목을 **탭**으로 전환한다(요약 · 취약점 · 석차 · 추이 · 문항). 맨 위에 같은 한 줄 결론. 관리자 전용으로 실명, 상담 참고(출결·휴대폰 기록)를 유지한다.
