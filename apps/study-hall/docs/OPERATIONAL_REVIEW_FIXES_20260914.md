## 운영 반영 순서

1. 다른 정책 작업과 위 공통 파일을 통합하고 전체 테스트를 다시 실행한다.
2. 기존 운영 환경에 `npm run db:deploy`로 `20260914180000_leave_attendance_snapshot`을 적용한다. 이 작업에서는 운영 마이그레이션을 실행하지 않았다.
3. Vercel Production에 별도의 충분히 긴 `CRON_SECRET`을 설정한다. `.env.example`의 빈 값은 예시이며 실제 비밀 값은 커밋하지 않는다.
4. 애플리케이션을 배포한다. `vercel.json`의 `10 15 * * *`는 UTC 기준으로 한국시간 00:10에 해당한다. Hobby에서는 지정 시간의 같은 시각대 안에서 지연될 수 있다. [Vercel Cron 문서](https://vercel.com/docs/cron-jobs/usage-and-pricing), [인증 관리](https://vercel.com/docs/cron-jobs/manage-cron-jobs).
5. 관리자 확정 정책이 켜진 지점에서는 cron이 벌점을 쓰지 않는지 확인한다. 자동 확정 지점은 첫 실행에서 정책 적용일부터 과거 날짜를 재계산하므로 적용 대상 기간·규칙을 먼저 확인한다.
6. 운영에서 수업 → 휴무 승인 → 취소의 결과, 새 파일 재가져오기 후 관리자/학생 성적 일치를 확인한다.
