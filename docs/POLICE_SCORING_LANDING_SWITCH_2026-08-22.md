## 현재 상태

- 운영 사이트에는 아무 변경도 반영하지 않았다.
- 기존 사전예약 대표 캠페인과 운영 단계는 그대로다.
- 새 가채점 랜딩은 로컬 전용 경로에서만 확인할 수 있다.
- 로컬 미리보기: `http://police.localhost:3200/local-preview/police-scoring`
- 로컬 산출 HTML: `apps/score-predict/.local/police-2026-second-scoring-promotion.html`
- 로컬 산출 명령: `pnpm --dir ./apps/score-predict promotion:export:police-scoring`

## 전환 구조

한 번의 운영 단계 적용으로 다음 두 값이 함께 바뀌어야 한다.

1. 운영 단계: `SCORING_OPEN` (`가채점 오픈`)
2. 대표 프로모션: 새 경찰 가채점 캠페인

`SCORING_OPEN` 기본값은 다음과 같다.

- 사전등록: 비공개
- 답안 입력: 공개
- 성적 결과: 공개
- 표본 분석: 비공개
- 최종예측: 비공개
- 공지사항: 공개
- FAQ: 공개

고급 기능 재정의를 사용하지 않고 회차 프리셋을 그대로 적용한다.

## 8월 22일 공개 순서

### 1. 코드와 정적 자산 배포

사용자가 별도로 배포를 지시한 뒤에만 진행한다. 현재 작업에서는 배포하지 않는다.

- 새 랜딩 코드와 `public/promotions/police/2026-second-scoring` 자산을 배포한다.
- 배포만으로 홈은 바뀌지 않는다. 대표 캠페인을 바꾸기 전까지 기존 사전예약 랜딩이 유지된다.
- 정적 자산 주소가 200인지 먼저 확인한다.
- 로컬 전용 미리보기 경로는 production에서 404가 정상이다.

### 2. 가채점 캠페인 생성과 게시

1. 경찰 관리자 `프로모션 관리`로 이동한다.
2. `HTML/CSS 자유 랜딩` 캠페인을 새로 만든다.
3. 로컬에서 생성한 `police-2026-second-scoring-promotion.html` 전체를 붙여 넣는다.
4. 390px, 768px, 1280px, 1920px 미리보기를 확인한다.
5. 임시저장 후 게시한다.
6. 아직 대표 캠페인은 바꾸지 않는다.

### 3. 수동 공개

관리자가 공개하기로 결정한 시점에 경찰 관리자 `사이트 설정 > 기능 및 운영`으로 이동한다.

1. 운영 단계를 `가채점 오픈`으로 선택한다.
2. 대표 프로모션을 새 경찰 가채점 캠페인으로 선택한다.
3. 고급 기능 재정의가 비어 있는지 확인한다.
4. 변경 결과 미리보기에서 `사전등록 비공개`, `답안 입력 공개`, `성적 결과 공개`를 확인한다.
5. `운영 단계 적용`을 누르고 확인 대화상자를 승인한다.

이 적용이 끝나면 기존 사전예약 랜딩은 미노출되고 새 가채점 랜딩만 홈에 표시된다.

## 공개 직후 확인

- 경찰 홈에 가채점 랜딩이 표시된다.
- 기존 사전예약 랜딩은 보이지 않는다.
- 히어로 CTA가 EVENT 01 위의 실제 시험 기능 UI로 이동한다.
- 실제 기능 UI에 풀서비스 메인·응시정보 입력·성적·합격예측·공지사항·FAQ가 운영 단계와 회원 상태에 맞게 표시된다.
- 로그인 회원이 `응시정보 입력`을 선택하면 기존 `/police/exam/input` 기능이 그대로 열린다.
- `/police/exam/input`에서 실제 OMR 입력이 가능하다.
- 소방 홈과 소방 회원, 시험, 성적에는 변화가 없다.
- 경찰 기존 회원, 사전등록, 제출, 성적 데이터는 그대로다.

## 문제 발생 시 즉시 되돌리기

가채점 기능은 열어 둔 채 랜딩만 안전하게 되돌린다.

1. 경찰 관리자 `사이트 설정 > 기능 및 운영`으로 이동한다.
2. 운영 단계는 `가채점 오픈`을 유지한다.
3. 대표 프로모션만 `기본 서비스 홈 사용`으로 바꾼다.
4. 적용 후 경찰 홈과 `/police/exam/input`을 확인한다.

시험 종료 후에는 랜딩 문제를 이유로 운영 단계를 `사전등록`으로 되돌리지 않는다. 그렇게 하면 OMR 답안 입력이 닫힌다.

## 데이터 안전성

- 이 랜딩 작업에는 Prisma 스키마 변경과 DB 마이그레이션이 없다.
- 회원, 아이디, 비밀번호, 사전등록, 시험, 제출, 성적 테이블을 수정하지 않는다.
- 전환 시 DB에서 바뀌는 값은 현재 회차의 운영 단계와 대표 캠페인 연결뿐이다.
- 대표 캠페인 변경 이력은 기존 운영 감사 로그에 남는다.
