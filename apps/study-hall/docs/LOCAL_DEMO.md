# 로컬 수동 테스트 데이터

이 데이터는 `MOCK_MODE=true` 로컬 개발 서버 전용입니다. 운영 DB와 연결하지 않습니다.

## 접속

- 관리자: http://localhost:3000/login — `admin-police@mock.local` / `demo1234`
- 조교: 같은 로그인 화면 — `assistant-police@mock.local` / `demo1234`
- 학생: http://localhost:3000/police/student/login — 수험번호 `91001`, 이름 `테스트 김민준`
- 공용 등원: http://localhost:3000/police/check-in — 기존 기기 등록 절차를 완료한 후 사용합니다.

로컬 모의 인증에서만 위 비밀번호를 사용합니다. 운영 계정이 아닙니다. 역할별 테스트는 서로 다른 브라우저 프로필 또는 시크릿 창을 권장합니다.

## 준비된 사례

| 화면 | 테스트 내용 |
| --- | --- |
| 학생·좌석 | 경찰 테스트 학생 32명, 재원·휴원·퇴원·수료, 테스트 자습실 |
| 출석·통계·학습 순위 | 출석·지각·결석·수업·사유·미처리, 대표 학생의 최근 5주 기록 |
| 등원 현황·학생 달력 | 최초 등원 시각, 늦은 등원, 미기록, 관리자 추가 이력 |
| 휴대폰 | 제출·미제출·대여 |
| 상벌점·경고 | 상점·벌점, 경고 단계별 대상, 안내 완료 이력 |
| 면담 | 진행·종결, 오늘 후속 확인, 보호자 연락 여부 |
| 성적 | 아침 시험 3주, 정기 시험 5회, 목표 점수, 전체 응시자 120명 기준 비교 |
| 성적 상세 | 최근 2회 대표 학생 2명의 문항별 정오답·취약 과목 분석 |
| 수납 | 완납·부분납·미납·일부 환불·면제 |
| 외출·휴가 | 대기·승인·거절·사용 사례 |
| 공지·일정·업무 메모 | 수정·삭제 가능한 테스트 콘텐츠 |

테스트 학생 이름에는 `테스트`, 업무 기록에는 `[목업]`을 표시합니다. 소방·올패스·한경 스파르타에도 각각 독립된 테스트 학생 12명과 관련 기록이 있습니다. 각 학원의 기존 규칙과 기능 설정은 유지하므로 비활성 기능은 표시되지 않을 수 있습니다. 공용 등원 기본 설정이 전혀 없는 학원에는 로컬 등원 설정만 추가합니다. 과거 설정 변경 이력이나 실제 기기 인증 정보는 만들어 내지 않습니다.

## 직접 확인 순서

1. 관리자 학생 명단에서 `테스트`를 검색합니다.
2. 상벌점·경고에서 테스트 학생별 점수와 단계를 확인합니다.
3. 성적에서 정기 시험을 선택하고 `테스트 김민준`의 상세 분석을 엽니다.
4. 등원 현황과 학생 출석 달력의 날짜·시각을 비교합니다.
5. 수납·면담·외출/휴가에서 수정과 저장을 테스트합니다.

입력된 출결과 휴가 사례는 화면 조작용 독립 데이터입니다. 휴가 승인이나 자동 벌점 처리 결과를 검증하려면 새 테스트 신청을 만들고 실제 승인·마감 절차를 수행하세요. 기존 운영 자동화는 켜지 않습니다.

## 다시 준비하기

Docker의 데이터 볼륨을 사용합니다. 호스트 `.local/mock-db.json`을 바꿔도 실행 중 서버 데이터에는 반영되지 않습니다.

```powershell
# 미리보기: 저장하지 않음
docker exec study-hall-dev-1 pnpm exec tsx scripts/seed-local-demo.ts
# 명시적으로 추가: 먼저 현재 데이터 백업, 기존 ID 보존
docker exec study-hall-dev-1 pnpm exec tsx scripts/seed-local-demo.ts --apply
```

새로운 ID만 추가하고 기존 학생·기록을 덮어쓰지 않습니다. 재실행의 중복 방지와 기존 기록 보존을 자동 검사합니다. 초기화/삭제 기능은 제공하지 않습니다. 백업과 적용 결과는 컨테이너 `.local/demo-backups`, `.local/demo-data-report.json`에 남습니다. 볼륨을 삭제하지 않는 정상 재시작에서는 테스트 데이터가 유지됩니다.
