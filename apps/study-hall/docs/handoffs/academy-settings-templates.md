# 다른 에이전트 전달: 학원별 운영 설정 템플릿

작성일: 2026-09-14
작업 경로: `D:\코딩\학원 포탈 프로그램\hankuk\apps\study-hall`

## 사용자 확정 요구

스터디홀은 각 학원이 자신의 시간표, 출결, 상벌점 규칙과 점수, 휴무·반휴권, 좌석 배치 등 모든 운영 항목을 직접 설정해서 쓰는 공통 앱이어야 한다. 경찰·소방별 별도 앱이나 고정 규칙으로 개발하지 않는다.

공통 템플릿을 선택해 초기 설정을 가져오고, 적용 후에는 해당 학원의 독립 설정으로 편집·운영한다. 경찰에서 만든 기능도 모든 학원이 설정에 따라 사용할 수 있어야 한다. 사용자가 요청한 템플릿은 화면 디자인 템플릿이 아니라 **운영 설정 묶음**이다.

## 구현 범위

| 설정 묶음 | 학원 관리자가 조정할 내용 |
| --- | --- |
| 시간표 | 교시명, 시작·종료 시각, 운영 요일, 필수·선택 자습, 적용 시작일, 휴강일 |
| 출석·지각 | 지각 판정 방식과 분 기준, 결석 판정, 인정 출석, 수업 인정, 통제 교시, 과거 수정 권한 |
| 상벌점 | 카테고리, 규칙명, 점수, 적용 조건, 사용 여부, 출결·시험·휴대폰 연동 |
| 상벌점 운영 규정 | 상·벌점 별도 집계 여부, 집계 기간, 경고 단계와 명칭·임계값, 자동 부여 또는 관리자 확정 |
| 휴무·반휴권 | 사용 여부, 월 한도, 적용 교시, 사전 신청·승인 조건, 병가, 미사용 보상·정산 방식 |
| 개근 | 일·주·월 계산 범위, 대상 요일·교시, 인정·제외 조건, 보상 점수 |
| 휴대폰 | 제출·대여 사용 여부, 일괄 대여 허용, 대여 시간·반납 기한, 반복 위반 기준 |
| 자습실·좌석 | 자습실 이름, 행·열, 통로, 좌석 라벨, 사용 여부, 배치도 |
| 기타 기존 설정 | 등록 요금제, 시험 종류·과목·일정·자동 상벌점, 학습 과정, 기능 사용 여부, 안내 문구 |

각 설정 묶음을 빠짐없이 조사하고, 설정 화면에서 편집할 수 있는 항목과 계산·조회·저장·자동 마감에서 사용하는 항목이 일치하도록 연결한다.

## 템플릿 사용 흐름

1. 관리자 설정에 템플릿 관리 진입점을 제공한다.
2. 공통 템플릿 선택, 우리 학원 설정을 템플릿으로 저장, 자체 템플릿 편집·복제를 지원한다.
3. 적용 전에 시간표·규칙·좌석 등 적용할 묶음을 선택하고 현재 값과 변경 예정 값을 미리 본다.
4. 템플릿 이름·버전·적용일·적용 범위·변경 이력을 기록한다.
5. 적용 완료 후 각 학원이 모든 값을 독립적으로 수정할 수 있어야 한다.
6. 원본 템플릿 또는 다른 학원의 설정 변경이 이미 적용한 학원에 자동으로 전파되지 않아야 한다. 재적용은 명시적인 별도 작업이다.

## 데이터와 권한 조건

- 설정·규칙·조회·계산·캐시·수정·삭제·배치 처리 모두 현재 학원의 `division_id` 또는 검증된 slug를 기준으로 한다.
- 일반 관리자는 자기 학원과 허용된 템플릿만 조회·적용할 수 있다. 다른 학원의 설정을 직접 읽는 방식으로 템플릿을 제공하지 않는다.
- 공통 템플릿 게시 권한과 학원 자체 템플릿 관리 권한을 구분한다.
- 템플릿의 교시·규칙·시험·자습실·좌석 참조는 대상 학원의 새 ID로 빠짐없이 재연결한다. 이름이 같은 항목을 단순 매칭하지 않는다.
- 학생·직원 계정, 출결·상벌점·수납 기록, 승인 내역, 선택자습 신청자, 좌석 배정 학생, 개인 연락처, 인증 정보는 템플릿에 넣지 않는다.
- 운영 중 학원에 적용할 때 기존 기록이 참조하는 교시·규칙·좌석을 삭제·재생성하지 않는다. 적용할 묶음의 병합·비활성화·새 적용기간을 설계하고, 필요한 변경은 미리보기에서 명확히 표시한다.
- 원자적 적용, 오류 시 전체 롤백, 동시 적용·중복 요청 방지, 적용 이력을 구현한다. mock과 실제 DB 경로의 보호 조건을 일치시킨다.
- 기존 운영 설정과 과거 확정 기록을 보존한다. 설정 변경으로 과거 점수가 바뀌는 경우는 별도 미리보기와 명시적인 재계산 작업으로 구분한다.
- 신규 자동화는 기본 비활성으로 두고 학원 관리자가 사용 여부와 적용일을 정한다. 특정 학원의 규정을 공통 기본값으로 강제하지 않는다.
- 개인정보가 없는 공통 설정 저장 구조, 스키마 버전, migration 및 기존 데이터 변환 경로까지 포함한다.

## 현재 코드에서 확인된 보완점

아래는 2026-09-14 로컬 소스 확인 결과다. 다른 에이전트의 변경이 있을 수 있으므로 시작할 때 다시 확인한다.

1. `lib/services/settings.service.ts`는 학원별 설정을 저장하고, 출결 연동 규칙이 해당 학원의 활성 규칙인지 검증한다. 기존 분리 구조를 유지한다.
2. `tardyMinutes`는 설정 저장·표시에만 나타나고 실제 지각 판정에 연결되어 있지 않다. 지각 기록의 실제 도착시각과 수동 입력을 구분하고, 학원의 판정 방식 및 분 기준을 계산에 연결한다. 과거 기록에 현재 도착시각을 임의로 만들지 않는다.
3. `lib/management-policy.ts`의 `lateArrivalPolicy`는 선언되어 있지만 계산 분기에서 사용되지 않는다. 정책의 `after_start` / `threshold`가 실제 동작하도록 한다.
4. `components/settings/RulesSettingsManager.tsx`는 policy가 있으면 지각 기준·지각/결석 규칙 입력을 잠근다. 관리자 편집 경로를 제공하고 일반 설정과 별도 정책의 이중 기준을 정리한다.
5. `lib/services/management-policy.service.ts`는 학원별 정책을 읽지만 전체 정책 편집 기능은 없다. `app/api/[division]/management-policy/route.ts`도 선택자습 등록·종료와 출결 확정만 지원한다.
6. `app/api/super-admin/copy-division-settings/route.ts`는 교시·상벌점·일부 운영 설정 복사에 한정된다. 좌석 등 전체 설정 템플릿으로 사용할 수 없다.
7. 위 복사 API의 mock 경로는 기존 교시·규칙을 교체하며, 복사한 settings의 관리규정·시험 자동화 등에 남을 수 있는 원본 ID를 전부 재연결하지 않는다. 실제 DB 경로도 삭제·재생성 방식이고 검사 범위가 출결·상벌점 기록에 한정되어 있다. 템플릿 기능에 그대로 재사용하지 말고 참조 관계와 운영 데이터 보호를 보완한다.

## 완료 검증

- 경찰·소방 이름에 의존하지 않는 서로 다른 두 학원으로 같은 템플릿을 적용한다.
- 각 학원의 교시·요일·지각 분·벌점·휴무/반휴권 한도·좌석을 서로 다르게 저장하고 실제 처리 결과가 각각 달라지는지 확인한다.
- 한 학원의 수정·원본 템플릿 수정·재적용·삭제가 다른 학원의 설정과 기록을 바꾸지 않는지 검증한다.
- 다른 학원 ID를 넣은 요청, 규칙·교시·좌석 ID 혼합 요청, 일반 관리자의 공통 템플릿 게시 등 권한 위반을 차단한다.
- 적용 전후 기존 출결·점수·좌석 배정·수납 내역을 비교하고, 실패·동시 요청·중복 요청에서도 데이터가 보존되는지 검증한다.
- 신규 학원·기존 운영 학원·자동화 비활성 학원 모두 확인한다. Asia/Seoul 월 경계와 적용일 경계를 검사한다.
- 타입 검사, lint, 기능·권한·학원 분리 테스트와 실제 브라우저의 템플릿 선택→미리보기→적용→개별 수정 흐름까지 검증한다.

## 현재 작업과 협업 경계

이 요청은 사용자가 다른 에이전트에게 전달하기로 했다. 현재 에이전트는 상벌점 규칙 설정 UI의 표·탭·슬라이드 모달 정리만 담당한다. 템플릿 기능이나 실제 학원 설정을 변경하지 않았다.

`components/points/PointRuleManager.tsx`와 `tests/render/point-rule-editor.test.ts`는 이번 디자인 정리·검증이 완료된 파일이다. `components/settings/SettingsPageShell.tsx`에는 모바일에서 현재 설정 메뉴가 보이도록 스크롤하는 보완도 포함한다. 기존 설정 탭 개편 등 미커밋 변경을 되돌리지 말고 작업 시작 시 변경 상태를 확인한다. UI는 `DESIGN.md`와 기존 `--admin-*` 토큰을 따른다. 로컬 구현·검증과 운영 DB 변경·배포를 구분한다.
