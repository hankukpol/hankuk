# 교시 설정과 출석부 연동

교시 설정의 활성 상태, 이름, 시작·종료 시간과 표시 순서를 관리자 출석부 및 조교 출석체크에 적용한다. 관리규정의 출석 교시 목록으로 입력 가능한 교시를 제한하던 동작을 제거했다.

## 적용 기준

- 활성 교시는 0교시·아침모의고사·저녁 자습·새로 추가한 교시를 포함하여 표시하고 출결을 저장할 수 있다.
- 비활성 교시는 입력 목록에서 제외한다. 기존 출결 기록은 삭제하지 않으며 재활성화하면 다시 조회할 수 있다.
- 일반 저장은 비활성 교시를 계속 거부한다. 반복 입력은 선택한 양 끝 교시 사이의 활성 교시만 적용한다. 비활성 교시를 끝점으로 전송한 오래된 화면의 요청은 거부한다.
- 관리규정이 적용되면 의무 출석, 출석률, 자동 벌점은 기존 요일·선택자습 신청 조건을 유지한다. 자율 교시에 기록한 결석을 의무 출석 결석이나 벌점에 추가하지 않는다.
- 관리규정 미적용 시 필수 여부는 교시 설정을 따른다. 아침모의고사의 출결 저장은 별도의 시험 응시·성적 기록을 대체하지 않는다.
- 교시 저장 후 출석·조교 페이지 캐시를 무효화한다. 출석 조회 응답은 `no-store`이며, 조교 화면의 `현재 교시 맞추기`도 최신 활성 교시 목록을 가져온다.
- 로컬 mock의 순서 변경이 기존 `displayOrder`로 재정렬되어 취소되는 문제도 수정했다.

- 0교시와 아침모의고사 출석 저장 API 200, 새로고침 후 두 기록 `PRESENT` 유지 확인.

- 390px 조교, 768px 조교, 1280px 관리자 및 기존 데스크톱 폭에서 화면 표시를 확인했다.

## 최신 main 통합 준비 (2026-09-14)

사용자의 전체 통합·배포 승인이 통합 담당을 통해 전달되어, 같은 격리 worktree를 `3a9688a`까지 fast-forward하고 교시 연동 변경을 다시 적용했다. `MobileCheckForm.tsx`의 `refreshCurrentPeriod` 충돌을 해결했다. 공용 main 수정·커밋·푸시·운영 배포는 통합 담당이 수행한다.

- 최신 main의 중복 저장 차단, 저장 중 추가 입력 보존, 임시 입력 복구, 날짜·교시 이동 보호를 유지한다.
- 교시 목록 갱신은 조회 시작 전과 응답 적용 직전에 모두 `requestCheckNavigation`을 거친다. 조회 중 새로 입력하거나 저장하기 시작해도 목록을 바로 바꾸지 않는다.
- 날짜·교시 이동 또는 뒤늦은 다른 갱신으로 오래된 응답이 된 경우 적용하지 않는다. 서버에서 새 교시 props가 와도 미저장 입력 보호를 거친다.
- `check-safety`에 실제 React/JSDOM으로 전체 목록 갱신·조회 중 추가 입력·명시적 폐기·활성 교시 0개·늦은 응답 무시 회귀 사례 2건을 추가했다.
- 통합 후 기존 교시/정책/상태 테스트와 출석/휴대폰 저장·날짜 보호 테스트 6개 파일 합계 65/65 통과. lint와 `tsc --noEmit --incremental false` 통과.
- 로컬 3015 실제 브라우저에서 비활성 5교시 제외, 다른 활성 교시 표시, 미저장 입력 후 `현재 교시 맞추기` 경고 및 결석 입력 유지, 저장 완료 후 새로고침해도 기록 유지 확인.

스키마·마이그레이션 변경 없음. 운영 설정·운영 출결 데이터 수정, 새 커밋·푸시·배포는 이 담당 작업에서 실행하지 않았다. 운영 반영 완료 여부는 통합 담당의 배포 결과로 확인한다.
