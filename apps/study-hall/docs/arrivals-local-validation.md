# 등원 체크 로컬 구현·검증 결과

검증일: 2026-09-15. 운영 DB·운영 서버에는 적용하지 않았다.

공용 기기에서 **기기 등록코드 받기** → 관리자의 등원 설정 **공용 기기 → 기기 승인**에 새 코드와 기기 이름 입력 → 공용 화면이 승인 상태를 확인하면 5자리 입력이 가능하다. 등록코드는 10분간 한 번 사용한다. 다른 포트·서버에서 만든 코드는 재사용하지 않는다.

로컬 3110의 경찰 학원만 테스트를 위해 사용을 켰다. 제품 기본값은 모든 학원 비활성, 5자리, 완료 팝업 1,200ms, 기기 인증 30일이다. 실제 관리자 로그인은 공용 기기와 별도로 한다.

## 구현 내용

- 공용 화면은 학원명·수험번호·키패드·안내만 표시한다. 앞자리 0을 보존하고 자릿수를 채우면 제출한다. 저장 중 키보드·터치를 잠그고 성공 후 번호 삭제와 포커스 복원을 수행한다. 이름·등원 시각·기록 목록은 표시하지 않는다.
- 당일 최초 접수 기록은 중복 입력에도 유지한다. 취소 뒤 재입력은 새 유효 시각으로 기록하며 이전 원본과 이력은 남긴다.
- 관리자 메뉴에서 출석 관리 바로 아래에 등원 현황을 추가했다. 날짜·검색·시각 정렬·오늘의 미기록 필터·5초 자동 갱신을 제공한다. 과거 미기록 인원을 현재 학생 명단으로 계산하지 않는다.
- 관리자 상세는 공통 월 달력과 정정 드로어를 사용한다. 추가·정정·취소 사유, 담당자, 처리 시각, 변경 전후를 보존하고 미래 입력과 동시 수정 충돌을 거부한다. 등원 기록이 있는 학생의 삭제 요청은 기록을 보존하는 퇴실 처리로 전환한다.
- 학생의 기존 출석 화면에 오늘 등원 시각과 월 달력을 추가했다. 본인 기록과 정정·추가 표시를 조회하며 기존 주간 교시 출석표를 유지한다.
- 학원별 설정에 적용일·변경 미리보기·예약·이력을 제공한다. 기기 인증과 관리자·학생 권한을 분리했고 학원 간 접근을 차단한다.
- 교시 출결, 출석률, 지각 판정, 상벌점, 성적, 학습시간 계산에 등원 기록을 자동 반영하지 않는다.

## 로컬 통합과 보존 범위

- 원본: `D:/Codex/worktrees/study-hall-arrivals-20260915/apps/study-hall`
- 3110 통합: `D:/Codex/worktrees/study-hall-academy-templates-20260914/apps/study-hall`
- 컨테이너: `study-hall-academy-settings-qa`, `MOCK_MODE=true`
- 등원 관련 44개 파일을 선별 병합했다. 충돌한 사이드바·모의 저장소·Prisma 스키마에서 기존 학원 템플릿·성적 정정 내용을 보존했다. 3110의 기존 셸에는 신형 모바일 도구 모음이 없어 기존 필터 바를 사용하도록 등원 목록만 맞췄다. 이후 공통 설정 셸에 선택 옵션을 추가해 새 등원 설정 화면의 모바일 제목 중복을 없앴으며 기존 사용처의 동작은 유지했다.
- 적용 전 소스·모의 데이터 백업과 파일별 해시: 원본 작업트리 `.local/integration-3110-20260915/`. 이후 추가 검증 수정은 등원 파일에 한정했다. 메인 작업트리에는 통합하지 않았다.

## 승인 전 남겨 둔 작업

커밋·푸시·DB 마이그레이션 실행·운영 배포는 수행하지 않았다. SQL은 `prisma/migrations/20260915210000_arrival_check_in/migration.sql`에 검토용으로 작성했다. 실제 PostgreSQL에서 마이그레이션·제약·트리거 실행 검증은 해당 작업 승인 후 수행해야 한다. 로컬 모의 데이터 검증을 운영 DB 적용 완료로 간주하지 않는다.
