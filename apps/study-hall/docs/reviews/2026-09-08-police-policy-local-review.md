# 경찰 스터디 홀 규정 적용 재검토

검토일: 2026-09-08. 기준은 제공받은 **학생규정집 및 준수동의서 v3.1의 벌점표**다. 지각 −2점, 정기모의고사 무단 미응시 −3점은 앞서 운영자가 결정한 기준을 유지했다.

이번 정리와 수정은 **로컬 코드에만 반영**했다. 운영 서버 배포, 운영 DB 변경, NAS 원본 수정은 하지 않았다. 앞서 배포된 별도 관리규정 페이지는 이번 수정분을 배포해야 운영 서버에서도 정리된다.

## 1. 별도 페이지 정리

| 기능 | 앞으로 사용하는 기존 메뉴 |
|---|---|
| 시간표와 평일 5교시 선택자습 신청·종료 | 관리자 → 설정 → 교시 설정 |
| 출결 벌점 후보 확인·확정·재확정 | 관리자 → 출석 관리 하단 |
| 휴대폰 예외 사전승인 | 관리자 → 휴대폰 관리 → 예외 사전승인 |
| 출결 변경으로 일반 체크 대상에서 빠진 대여자의 반납 | 휴대폰 체크 하단 → 출결 변경 학생의 반납 대기 |
| 반복 중도퇴실·무단입실·휴대폰 예외 검토 | 관리자 → 경고 대상자 |
| 상벌점 항목과 점수 | 기존 상벌점 규칙 메뉴 |

관리자·조교·학생 탐색에서 별도 관리규정 메뉴를 제거했다. 기존 관리자 주소는 운영 규칙 설정으로, 조교 주소는 출석체크로, 학생 주소는 출석 상세로 이동한다. 출결·신청·승인 서비스와 저장 데이터는 유지했다.

## 2. 규정과 실제 처리 대조

| 항목 | 기준 및 검증 결과 |
|---|---|
| 시간표 | 0교시 06:00~08:00, 아침모의 08:30~09:00, 1교시 09:15~10:45, 2교시 11:00~12:30, 3교시 13:45~15:15, 4교시 15:30~17:00, 5교시 18:15~19:55, 6교시 20:10~21:50. 마감 22:00. 문서·설정 일치 |
| 통제 범위 | 월~토 1~4교시, 평일 5교시는 신청한 학생·날짜·요일만 적용. 토요일 5교시와 일요일은 벌점·휴대폰 의무 대상에서 제외 |
| 출석 입력 | 1~5교시 기록. 조교는 설정에 따른 날짜 범위에서 입력하며, 현재 기본값은 당일만 허용. 관리자 과거 정정 가능 |
| 지각 | 조교 또는 관리자가 지각 상태를 기록하면 후보 −2점. 관리자 확정 전에는 자동 벌점 없음. 재확정 중복 없음 |
| 전체 무단결석 | 해당 학생의 마지막 통제교시 종료 후 모든 통제교시가 결석일 때 하루 −5점 1건. 임의의 교시별 결석 −2점은 만들지 않음 |
| 인정사유 정정 | 사유결석 등으로 정정 후 같은 날짜를 재확정하면 그 날짜의 기존 자동 출결 벌점을 해제. 수동 부여 기록은 보존 |
| 선택자습 | 신청 저장, 겹치는 신청 거절, 종료 시 오늘·과거 신청 보존. 같은 기간이라도 다른 요일 신청은 함께 삭제하지 않음 |
| 휴일권 | 월 2회. 사전 통보 원칙, 당일·과거 신청에는 인정사유 필요. 승인 시 대상 통제교시의 휴무 출석을 연결하고 취소 시 연결 기록만 해제 |
| 병가 | 증빙·인정사유를 확인하여 횟수 제한 없이 처리. 미사용 휴일권 보상에서 차감하지 않음 |
| 외출·정기 일정 | 외출은 승인 이력을 남기며 하루 전체 출결을 덮지 않음. 대상 교시의 인정사유는 출석부에서 입력. 반복 일정은 기존 출석 일괄 적용의 기간·요일·교시·사유 기능으로 처리 |
| 휴일권 미사용 | 미사용 1개당 +2점. 재원 기간을 확인하여 월 마감 후 대상 월에 귀속. 같은 월 반복·동시 정산의 중복 지급 차단 |
| 월 상벌점 | 상점·벌점을 별도 집계하고 상계하지 않음. 전월 원기록 유지. 상점 +30, 벌점 −25 입력 시 벌점 25점 단계 유지 |
| 경고·반복 관리 | 월 벌점 10/20/25/30 기준. 최근 7일 무사유 중도퇴실 2회 면담·3회 개선미션, 월 무단입실 2회 심의, 최근 7일 휴대폰 예외 3회 검토 |
| 휴대폰 단기 반출 | 사유 필수, DB 기준 10분 기한 기록. 재저장으로 최초 반출 시각·횟수를 바꾸지 않음 |
| 휴대폰 사전승인 | 관리자만 시간·장소·목적 승인 가능. 기존 기한 안의 추가 승인 기록을 보존하고 기한 경과 후 사후 연장 차단 |
| 휴대폰 반납 | 반출 후 사유결석·외출 처리된 학생도 실제 반납 기록 가능. 반출·승인·반납 이력 유지. 이 학생의 반납 버튼도 실제 브라우저에서 확인 |
| 직렬 분리 | 검증 전후 소방 설정과 운영 기록 전체 비교 결과 불변 |

활성 상벌점 규칙 19개는 학생 벌점표 13개와 상점표 6개에 일치한다. 정기모의고사 1~3등은 +3/+2/+1, 아침모의 1등 +3, 아침모의 한 달 개근 +3, 미사용 휴일권 개당 +2다.

## 3. 이번에 고친 오류

- 지각을 다시 저장할 때 최초 기록 시각이 바뀌던 문제를 수정했다. 과거 지각을 등록할 때 오늘 시각을 잘못 넣지 않는다.
- 승인결석·휴무·미처리를 실제 출석과 구분하여 출결 집계를 수정했다. 비활성 교시는 입력·예상 출석 대상에서 제외한다.
- 선택자습 종료 시 같은 기간의 다른 요일 신청까지 끝나던 문제를 수정했다.
- 병가가 미사용 휴일권 상점을 줄이던 문제, 정산월 이후 신규 등록생에게 전월 보상을 주던 문제, 동시 정산 중복 지급을 수정했다.
- 날짜를 생략한 상벌점 부여가 한국시간 월초에 전월로 저장될 수 있던 문제를 수정했다.
- 휴가 승인·취소가 선택자습 신청자의 5교시까지 반영되도록 수정했다.
- 이미 대여 중인 휴대폰의 승인 권한 검사를 건너뛰거나 관리자 승인을 무시하던 문제를 수정했다. 메모 재입력으로 반출 횟수를 부풀리지 않도록 했다.
- 출결이 바뀐 대여자의 실제 반납이 막히던 문제를 수정하고 기존 휴대폰 화면에서 처리할 수 있게 연결했다.
- 반복 위반 검토에서 퇴실생·정책 시행 전 반출·깨진 날짜를 제외했다.
- 휴가 화면과 운영 규칙 요약에 남아 있던 병가 월 1회 안내, 자동 벌점처럼 보이던 문구를 정리했다.

## 4. 직원 확인이 필요한 범위

**프로그램이 규정 전체를 자동 집행하는 상태라는 뜻은 아니다.** 다음은 기존 기능에서 직원이 확인·입력해야 한다.

| 업무 | 실사용 방법·한계 |
|---|---|
| 실제 지각 판정 | 출입기기나 실제 도착시각 입력에 따른 자동 판정 기능은 없다. 직원이 출석/지각을 선택한다. 오늘 첫 지각 입력 시각을 기록하며, 과거 지각의 실제 시각을 만들어 넣지 않는다 |
| 같은 행위 벌점 중복 | 한 행위는 가장 중한 항목 하나로 기록한다. 같은 학생·날짜·규칙의 수동 벌점이 있으면 자동 출결 후보가 제외되므로, 같은 날 여러 교시 지각을 수동·자동 혼합 부과할 때 직원이 내역을 확인해야 한다 |
| 외출·재입실 | 승인 이력과 출석 사유는 기록하지만 출입문을 자동 통제하지 않는다. 긴급사유 인정, 건물 밖 이탈, 다음 휴식시간까지 대기 여부는 현장에서 확인한다 |
| 휴대폰 사용 | 15분 휴식 일반 반출 금지, 식사 후 시작 10분 전 재제출, 사용 장소·목적·실사용폰 여부는 직원 확인 사항이다. 기한 기록만으로 자동 벌점을 확정하지 않는다. 장시간 일괄 대여 요청은 API에서 거절한다 |
| 시험 상점·미응시 벌점 | 시험 결과·인정사유 확인 후 기존 상벌점 메뉴에서 해당 규칙으로 부여한다. 시험 성적 입력만으로 모두 자동 지급·부과하는 기능은 아니다 |
| 순찰·학습목표·심의 | 비정시 순찰 3회, 당일 졸음 단계, 목표 3개, 3일 이의신청, 개선미션·즉시 퇴실심의의 판단은 직원 업무다. 전용 자동 순찰·전자동의·이의신청 기능을 새로 추가하지 않았다 |

## 5. 문서에서 정리할 차이

NAS의 원본 3개를 ZIP/XML로 다시 읽고 SHA-256을 기록했다. 이전 검토 추출문과 공백을 제외한 내용은 모두 동일했다.

| 수정할 표현 | 통일 기준 |
|---|---|
| 학생 Q&A의 ‘20분 이내 지각 −1점’ | 교시 시작 후 도착 지각 −2점 |
| 학생·관리자 본문의 정기모의 미응시 −2점 | 학생 벌점표 −3점 |
| 관리자 문서의 ‘교시결석 −2’와 지각 혼용 | 지각 −2, 관리일 전체 무단결석 −5. 별도 교시결석 −2 자동 부과 없음 |
| 조교 문서 일부의 휴대폰 재제출 지연 −1점 | 학생표에 독립 항목 없음. 미제출·무단소지 또는 승인시간 초과 등 실제 행위에 맞춰 관리자 판단 |

## 6. 검증 근거와 한계

- 단위·회귀 테스트 **248/248** 통과. 이 중 이번 규정 서비스 검증은 출석 16개, 휴가·상벌점 18개, 휴대폰 12개를 추가했다.
- 전체 API 권한·직렬·잘못된 입력 검사 **323/323** 통과.
- 별도 규정 HTTP 시나리오 **18/18** 통과: 출결·선택자습·휴일권·정산·월별 상벌점·휴대폰·권한·소방 불변.
- 프로덕션 빌드와 기존 운영 smoke 시나리오 통과. 최종 UI 안내 정리 후 타입 검사·ESLint 추가 통과.
- 브라우저에서 지각 저장 → 후보 −2 → 관리자 확정, 선택자습 날짜 입력·신청·종료, 휴대폰 승인 → 출결 변경 → 반납을 직접 처리하고 저장 기록을 대조했다.
- 출결 확정·휴대폰 승인 화면은 390/768/1280px에서 확인했다. 문서 가로 넘침 없음. 기존 디자인 토큰 검사도 통과했다.
- **로컬 JSON 모의 데이터 기반 검증**이다. 실제 PostgreSQL 연결 테스트는 하지 않았고, DB 분기는 Prisma 호출 계약·동시성 조건을 대역으로 검증했다. 운영 환경 정상 동작이나 운영 배포 완료를 뜻하지 않는다.
- 완료된 날짜·전월 정산을 시험하려고 테스트 fixture에서만 적용일을 2026-08-01로 앞당겼다. 실제 배포 manifest의 2026-09-08 적용일은 바꾸지 않았다.

증거: `.local/policy-review/`의 문서 해시, API 결과, 저장 데이터 대조, unit/lint/typecheck 로그. 전체 빌드·API 로그는 `.local/test-b5a89de3/integration.log`. 화면 증거는 `.superloopy/evidence/frontend/2026-09-08-policy-workflows/`.

재검증: `pnpm test`, `pnpm test:integration`. 규정별 HTTP 점검은 `scripts/start-policy-review.mjs`로 별도 fixture 서버를 만든 뒤 `scripts/check-policy-review.mjs`, `scripts/check-policy-phone-review.mjs`를 실행한다. 두 점검 스크립트의 업무일은 이번 검증일인 2026-09-08이며, 이후 날짜의 재검증에는 날짜 fixture 조정이 필요하다.
