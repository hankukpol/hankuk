## 공통 구현

- AdminDrawer: 표준 header/body/footer, 44px 닫기, 직각 외곽, min(760px, 100%) 폭, 화면 높이.
- AdminDrawerSurface: 기존 복잡한 본문/제출 구조를 보존하는 같은 슬라이드 표면.
- AdminPortal: #admin-portal-root 안에서 폰트·테넌트 색을 상속한다. root가 없는 독립 소비자는 인라인 유지.
- useModalDialog: 최상위 창의 Escape/Tab, 배경 inert·스크롤 잠금, 원래 버튼 포커스 복귀.
- 저장·취소는 스크롤 본문 밖에 고정한다. 별도 form id를 쓰던 제출 계약도 유지한다.
- 직원/팝업/강좌 등록·편집의 중복 제출과 통신 오류를 처리하며 실패한 초안은 유지한다.
- 결제/환불 데이터, API 주소·payload, 메모 저장 단위와 접근 권한은 바꾸지 않는다.

## 검증 경계

소스 점검은 관리자/결제 표면 전체를 대상으로 한다. 실제 브라우저에서는 데이터가 있는 대표 흐름을 390/768/1280px와 짧은 화면에서 확인하고, 생성·삭제·환불 저장은 실행하지 않는다. 데이터 변경/실패/재시도는 mock fetch 기반 React 통합 테스트로 확인한다. 이 문서는 모든 권한의 모든 업무를 실데이터로 실행했다는 뜻이 아니다.

이번 증거: `.superloopy/sessions/20260905-admin-drawer-consistency/evidence/`.

검증 결과: 관리자 UI 회귀 테스트 129개 통과, 관리자/결제 표시 규칙 소스 79곳 검사 통과, 브라우저 19개 화면 상태 측정 통과, TypeScript `--noEmit --incremental false` 및 `git diff --check` 통과. 상세 관찰 범위와 미실행 경계는 해당 증거 폴더의 `VISUAL_QA.md`에 기록한다.
