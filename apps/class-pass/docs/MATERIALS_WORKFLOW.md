# 배부자료·교재 관리 개선 (2026-09-05)

## 현재 디자인 기준

화면 규격은 [DESIGN.md](../DESIGN.md)의 관리자 기준을 따른다. 자료 탭은 한 페이지형 섹션, 하위 메뉴는 직선 밑줄형 탭이며, 아래 기능·검증 이력은 별도 디자인 시스템이 아니다.
자료 폼·회차 모달·수령 표에 적용할 클래스와 확인 방법은 [디자인 구현 안내](DESIGN_IMPLEMENTATION.md)를 참고한다. 이 문서의 과거 테스트 결과는 해당 실행 시점의 기록으로 보존한다.

## 사용 방법

### 지난 프린트로 다음 회차 만들기

1. 강좌 → 자료 → 배부자료에서 기존 자료의 **다음 회차 만들기**를 선택합니다.
2. 원본의 설명과 배부 대상 과목은 그대로 사용합니다.
3. 이름에 `3회차` 또는 `3주차`가 있으면 다음 회차를 제안합니다. 이름을 인식하지 못하면 직접 시작 회차를 입력합니다.
4. 이름 미리보기를 확인한 뒤 생성합니다.
5. 새 자료는 **비활성**입니다. 목록의 수정에서 이름과 대상을 확인하고 활성화합니다.

### 여러 주 자료 한꺼번에 준비하기

1. 자료 목록 위의 **여러 회차 만들기**를 선택합니다.
2. 이름 규칙을 `경찰학 {회차}회차 프린트`처럼 입력합니다.
3. 시작 1, 마지막 4를 입력하면 1~4회차 이름이 미리 표시됩니다.
4. 공통 설명과 배부 대상 과목을 지정합니다. 전체 배부는 좌석 배정과 무관하며, 과목을 지정하면 해당 과목 좌석 배정자만 대상입니다.
5. 한 번에 최대 52개, 회차 번호는 1~999, 최종 이름은 100자 이내입니다.

새 회차는 별도의 자료 ID를 사용합니다. 기존 수령 기록·교재 구매/배정 기록은 복사하지 않습니다. 비활성 자료는 배부 대상에 나타나지 않습니다.

## 안정성 보완

- 교재 배정 조회가 1,000행에서 끊기지 않도록 전체 페이지를 읽습니다. 서버의 실제 반환 상한이 더 작아도 누락 없이 다음 페이지를 읽습니다.
- 교재 일괄 배정은 학생별 성공/실패를 구분합니다. 성공한 학생은 반영하고, 미확인 학생만 선택 상태로 남겨 재시도합니다.
- 자료 생성·수정과 교재 배정은 통신 오류가 나도 처리 중 상태가 해제됩니다. 저장 여부가 불확실한 경우 확인 방법을 한국어로 안내합니다.
- 과목별 자료의 미수령 필터에서 해당 과목 좌석이 없는 학생은 제외합니다.
- 처리 중 탭·대상 필터·선택 변경을 막습니다.
- 교재 미구매 표시는 유지합니다. 수강등록 시 선결제 여부와 이후 구매 상황을 다루는 기존 업무 의미를 변경하지 않습니다.

## 재시도 시 주의

- 인터넷 오류는 저장 실패를 확정하는 뜻이 아닙니다. 먼저 목록 또는 배정/수령 현황을 새로고침합니다.
- 회차 생성은 자동 재시도하지 않습니다. 동일 이름이 이미 있으면 서버 사전 검사에서 안내합니다.
- 한 창에서의 연속 생성 클릭은 차단하지만, 여러 관리자가 동시에 같은 이름을 만드는 경우를 DB 고유 제약으로 강제 차단하지는 않습니다. 동일 회차의 동시 생성은 피합니다.
- 기존 자료에 수령 기록이 있을 때 이름/과목을 바꾸면 과거 자료의 의미도 바뀔 수 있으므로, 반복 프린트는 새 회차로 생성합니다.

## 1차 기능 구현 검증 기록

- 신규 회귀 테스트 8건 통과: `tests/admin/material-safety.test.ts`, `tests/admin/material-workflows.test.tsx`.
- 기존 배부 테스트 7건 통과. 중간 타입 검사 및 프로덕션 빌드는 통과했습니다. 이후 동시 작업의 환불 코드 변경이 반영된 최종 빌드는 `src/app/api/payments/refunds/route.ts:64`에서 `CreateRefundBundleInput.requestId` 누락으로 실패했습니다. 환불 파일은 이번 작업에서 수정하지 않았으며 배포 전 통합 재검증이 필요합니다.
- 전체 관리자 테스트는 61건 중 60건 통과. `student-row-actions.test.tsx`의 메모 버튼 기대값 1건 실패. 해당 테스트와 명단 테이블은 이번 변경에서 수정하지 않았으며 별도 관리자 UI 작업과 확인이 필요합니다.
- 최종 타입 재검사 시점에는 환불 계약 변경에 이어 `src/lib/payments/integrity.ts:202`의 `"closed"` 값과 `BillingStatus` 불일치가 확인됐습니다. 공유 작업 폴더의 환불·정산 작업이 계속 변경 중이므로, 해당 작업이 끝난 뒤 전체 타입·빌드·관리자 테스트를 다시 실행해야 합니다.
- 통과했던 중간 빌드에서는 기존 super-admin 사전 렌더링의 Supabase 환경 미설정 로그 2건이 있었습니다. 운영 환경변수 검증을 대신하는 결과는 아닙니다.
- 실제 로컬 브라우저에서 390/768/1280px 모달 미리보기, 입력 오류 안내, 스크롤을 확인했습니다. 브라우저에서는 생성 버튼을 실행하지 않았습니다.
- API/저장/실패 테스트는 전부 메모리 모의 데이터로 실행했습니다. 실제 운영 데이터 생성·수정·삭제 없음.
- DB 스키마 변경과 마이그레이션 없음. Git 커밋·푸시·Vercel/Supabase 배포는 수행하지 않았습니다.

서버 구현 참고: [Supabase 여러 행 insert 공식 문서](https://supabase.com/docs/reference/javascript/insert).

## UI 정리 및 후속 검증 (2026-09-05, 위 기록 이후)

- 폰트 계층·입력/목록 배치·회차 미리보기의 현행 치수는 [DESIGN.md](../DESIGN.md)의 3절과 5.12절에 통합했습니다. 자료 추가·수정은 같은 입력 컴포넌트를 쓰며 전체·활성·비활성 요약은 빈 칸 없이 세 칸입니다.
- 회차 모달은 5.10절의 공통 제목·본문·하단 작업·X 닫기 규격을 사용합니다. 표와 서브 탭은 직각, 일반 컨트롤과 중앙 모달 외곽은 8px입니다.
- 미구매/대상 아님 상태의 대비를 높였습니다. 자료명 필터는 키보드로 조작할 수 있고 선택 상태를 알립니다. 일괄 처리 중 수령 취소도 비활성화됩니다.
- 관련 테스트 **17/17 통과**: 자료·교재 안정성 7건, 실제 React 화면 흐름 1건, 표시 규격 2건, 기존 배부 테스트 7건. API 호출은 메모리 모의 데이터로만 실행했습니다.
- 최신 `tsc --noEmit` 통과. 중간에 확인한 환불/정산 타입 오류는 최신 검사에서 재현되지 않았습니다.
- 최종 코드 기준 `pnpm build` 통과. 다만 super-admin 사전 렌더링에서 Supabase 환경 미설정 로그 2건이 남습니다. 운영 환경변수 검증은 별도이며 값을 출력하거나 변경하지 않았습니다.
- 최신 전체 관리자 테스트 **75건 중 70건 통과, 5건 실패**. 모두 별도 작업 범위의 `tests/admin/refund-drawer-safety.test.tsx`입니다: 불확실한 환불 응답 처리 3건, 환불 후 잔액 즉시 반영 1건, 수강 종료 버튼 1건. 해당 구현·테스트는 이 자료 UI 작업에서 수정하지 않았습니다.
- 390/768/1280px 로컬 브라우저에서 자료 입력·빈 목록·회차 미리보기와 기존 설정 화면의 글꼴을 비교했습니다. 가로 문서 넘침 없음. 데이터가 있는 목록/수령 표의 상태 전환은 React 모의 데이터 테스트로 확인했으며, 실제 운영 자료를 생성해 검증하지 않았습니다.
- 통합 배포 준비가 완료됐다는 뜻은 아닙니다. 별도 환불 작업을 마친 뒤 전체 관리자 테스트를 다시 통과해야 합니다. 커밋·푸시·배포와 운영 데이터 변경은 하지 않았습니다.
