관리자·조교·학생 운영 흐름의 로컬 QA를 수행하고, 재현한 결함을 수정했다. 최종 회귀 테스트 891개, HTTP 통합 테스트 427개, 격리 배포용 빌드가 통과했다. 현재 app/components/lib/prisma 파일을 검증 빌드 `.local/test-685a4d2d`와 해시 비교하여 차이 0건을 확인했다.

운영 DB 변경, Git 커밋·푸시 및 운영 배포는 하지 않았다. 이 문서는 운영 서버 반영 확인서나 모든 환경에서 결함이 없다는 보증서가 아니다.

## 재현 후 수정한 결함

1. 휴가 미사용 상점 정산 뒤 과거 휴무 승인·취소 시 상점이 갱신되지 않음: 기존 자동 정산 기록의 금액을 정정하고 변경 이력을 저장한다. 수동 상점과 타 학원 기록은 보존한다.
2. 자동 점수 계산 실패가 정상 저장으로만 표시됨: 출결 원본은 보존하면서 부분 성공 경고를 반환하고 재계산 경로를 제공한다. 영구 백그라운드 재시도 큐를 새로 구현한 것은 아니다.
3. 단순 외출 이력만으로 시험 미응시가 면제됨: 외출 이력 자체는 면제하지 않고, 승인된 해당 출결 사유·휴무·반휴를 사용한다.
4. 월별/수강기간 및 별도/상계 설정과 실제 점수·경고가 불일치: 학원 정책과 같은 범위로 집계하며 수강 전 기록을 기본 수강기간 합계에서 제외한다. 원장은 보존한다.
5. 시간표 변경이 과거 학습 시간과 성적 동점 순위를 변경함: 출석 날짜에 적용된 교시 설정으로 계산한다.
6. 교시 삭제·비활성화 후 과거 학습 시간의 교시별 내역이 사라짐: 기록이 있는 과거 교시를 표시한다.
7. 경고 필터가 학원별 단계명을 반영하지 않음: 유효한 학원 설정의 단계명을 필터에 연결한다.
8. 같은 시각의 mock 휴가 생성 ID 충돌 및 공용 기기 API 테스트 계약 오류도 함께 보완했다.

## 검증 한계

HTTP 및 브라우저 QA는 격리 mock 런타임이다. 실제 PostgreSQL 검증은 별도 로컬 DB에서 선택한 핵심 서비스·트랜잭션에 대해 수행했다. 실제 Supabase Auth/RLS, 다중 서버 인스턴스, 모든 물리 기기·대용량 파일·네트워크 장애 조합을 검증했다고 주장하지 않는다. 공유 3000 개발 서버의 간헐적 응답 지연/HMR 현상도 격리 빌드 결과와 구분한다. 정산 정정 이력은 저장하며 전용 이력 UI는 이번 변경에 포함하지 않았다.
