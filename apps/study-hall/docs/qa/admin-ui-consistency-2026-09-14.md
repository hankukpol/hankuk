# 학원 관리자 UI 일관성 점검

- 기준: `DESIGN.md`, `MOBILE_DESIGN.md`, `app/globals.css`의 공통 관리자 토큰.
- 환경: 로컬 Docker mock, `http://localhost:3000`, 2026-09-14.
- 범위: `app/[division]/admin`의 30개 페이지 진입점. 학생/조교 포털과 플랫폼 최고관리자 페이지는 이번 추가 수정 대상이 아니다.
- 기존 작업 및 다른 에이전트의 변경을 보존했다. 학원별 템플릿 백엔드, 운영 DB, 배포는 변경하지 않았다.

## 이번 수정

| 화면 | 변경 |
| --- | --- |
| 직원 관리 | 2열 입력/목록을 단일 표로 전환. 검색/권한/상태 필터, 모바일 필터 접기, 생성/수정 드로어, 별도 비밀번호 드로어 |
| 시험 일정 | 일정 표와 생성/수정 드로어. 저장 실패 시 초안 유지, 저장 후 목록 갱신, 날짜순 유지 |
| 시험 템플릿 | 정렬 가능한 표와 생성/수정/복사 드로어. 키보드 정렬 지원, 복사 시 기존 과목 ID 제외 |
| 자습실·좌석 설정 | 자습실 목록/좌석 배치 2개 탭. 자습실 표, 생성/수정 드로어. 취소 시 구조와 좌석 초안 및 미저장 상태 복원 |
| 학생 상세 | 기본 정보는 읽기 전용 항목표, 정보 수정/메모 수정은 드로어. 주요 수정 버튼을 상단 배치. 한국 시간 기준 날짜 표시, 운영 기록의 AM/오전 차이로 발생하던 초기 렌더링 오류 수정 |
| 공통 셸 | 직원/상벌점 규칙의 모바일 제목을 실제 페이지명과 일치시킴 |

새 색상이나 화면별 CSS 토큰은 추가하지 않았다. 표, 필터, 보조 탭, 항목표, 고정된 드로어 하단 버튼은 기존 공통 컴포넌트와 클래스를 사용한다.

## 경로 점검표

경로는 `/{division}/admin` 기준이다. '브라우저'는 mock 관리자 계정으로 실제 렌더링과 기본 진입 상태를 확인했다는 뜻이며, 모든 데이터/권한/하위 상태를 전수 실행했다는 뜻은 아니다.

## 검증

- 실제 브라우저에서 주요 24개 메뉴/설정 화면과 학생 상세의 렌더링을 확인했다. 확인한 기본 상태의 문서 가로 넘침은 0px였다.
- 1280px 데스크톱, 768px 중간 폭, 390px 모바일에서 대표 변경 화면을 확인했다. 모든 경로를 모든 폭에서 교차 검증한 것은 아니다.
- 직원, 자습실, 시험 일정, 시험 템플릿의 표와 편집창을 확인했다. 모바일 드로어 폭, 닫기 버튼, 하단 저장/취소 버튼과 폼 연결을 확인했다.
- 학생 정보 수정창 열기/취소, 메모 초안 입력/계속 편집/변경 폐기를 브라우저에서 확인했다. 서버 저장은 하지 않았다.
- 자습실 크기 변경 후 취소하여 원래 크기로 돌아오는 동작을 브라우저와 테스트에서 확인했다.
- 직원 모바일 필터 접힘, 선택된 설정 탭의 직접 진입 및 화면 폭 변경 후 노출을 확인했다.
- `pnpm typecheck`: 통과.
- `pnpm lint`: 통과, 경고/오류 없음.
- `admin-settings-drawers.test.ts`, `settings-tab-layout.test.ts`, `point-rule-editor.test.ts`: 18개 테스트 통과.
- `settings-features.test.ts`: KST 날짜 경계와 설정 검증 23개 통과. 두 테스트 실행 합계 41개 통과.
- 학생 상세 직접 새로고침과 운영 현황 탭 전환 후 시간 텍스트가 `YYYY-MM-DD HH:mm`으로 일치하며 새 hydration 오류가 발생하지 않는 것을 확인했다.
- 디자인 규격 검사(`ds-compliance.mjs`)와 `git diff --check`: 통과.
- Docker 개발 서비스 `healthy`, 호스트 3000번 연결 확인.

## 검증 한계와 환경 메모

- 저장/삭제/비밀번호 변경의 성공·실패 경로는 격리된 React/JSDOM 테스트의 모의 API로 검사했다. 실계정 비밀번호 변경이나 운영 데이터 삭제는 실행하지 않았다.
- 전체 생산 빌드, Lighthouse, 운영 배포 검증, 모든 권한/기능 비활성 조합은 실행하지 않았다.
- 개발 중 Next.js의 오래된 모듈 캐시 오류가 발생해 생성된 `.next-dev` 캐시만 비우고 재시작했다. 데이터 볼륨은 유지했으며 이후 대상 페이지가 정상 렌더링되는 것을 확인했다.
- mock 좌석 데이터의 요약/배정 수 불일치는 기존 데이터 상태이며 이번 UI 작업에서 데이터를 정리하지 않았다.
