# 상벌점 4.1·4.2 반영 안내

명세: [point-policy-revision.md](point-policy-revision.md). 4.3은 착수하지 않는다.

## 운영 반영 순서

이 작업에서는 운영 DB를 변경하지 않는다. 다음은 운영자가 실행할 절차다.

1. 운영 DB를 백업한 뒤 `20260914190000_perfect_attendance_week_month` 마이그레이션을 적용한다. 새 주간·월간 설정은 모두 **0**이며 기존 일일 설정은 바꾸지 않는다. `ADD COLUMN IF NOT EXISTS`로 재실행 가능하다.
2. 코드 배포 뒤 관리자의 규칙 설정 화면이 정상적으로 열리는지 확인한다.
3. [운영 반영 SQL](sql/point-policy-revision-41-42.sql)을 검토하고 실행한다. 경찰반 RESTART 정책만 대상으로 교시 결석 −2 연결, 종일 결석 −9, 주간 +2·월 +2를 활성화하고 일일 개근은 꺼 둔다. 조교의 관리자 확정 우회, 상계, 다른 벌점·임계값·월 리셋을 변경하지 않는다.
4. SQL은 지각 규칙과 기존 정책이 검토한 상태인지 확인한 뒤 적용하며, 같은 상태에서 재실행해도 규칙이 중복되지 않는다. 기존 상벌점 기록·출석은 재작성하지 않는다. SQL 이후 설정 화면을 새로고침하고 새 출석 저장/관리자 확정에서 확인한다. 캐시가 남으면 배포 재시작 또는 설정 화면에서 저장하여 갱신한다.
5. 운영 문서에 기록된 `기본이론 수업 수강` 52행은 운영자가 출석 화면에서 **수업: 기본이론**으로 다시 저장해야 한다. `isClassAttendance`는 변경하지 않았으므로 이전 문구는 개근으로 인정되지 않는다.

## 판정과 기록

- 한 주는 월요일~일요일, 한 달은 달력 월이다. 규정 적용일 이후의 관리 교시만 판정한다. 선택 통제 교시는 기존 `isControlledPeriod`가 해당 학생에게 의무로 판정할 때 포함된다. 토요일 저녁·일요일 자율·아침모의고사는 제외한다.
- 모든 대상 칸이 PRESENT 또는 기존 `isClassAttendance`에 맞는 수업이어야 한다. 일반 사유·휴일권·미입력도 개근 출석을 충족하지 않는다.
- 출결에 별도 중도퇴실 상태가 없다. 무단중도퇴실을 해당 교시 결석으로 기록하면 개근에서 제외된다. **수동 벌점만 기록하고 출결을 PRESENT로 남긴 경우는 출결만으로 감지할 수 없다.** 명세대로 상벌점 기록을 개근 판정에 섞지 않는다.
- 마지막 관리 교시가 끝난 뒤 출석 저장 시 지급한다. 교시 시작 때 모든 칸을 입력한 경우 다음 저장에서 직전 주·월도 마감한다. 이 작업에 예약 작업은 추가하지 않는다.
- 주간 노트는 `[자동] 주간 개근 상점 (YYYY-MM-DD~YYYY-MM-DD)`, 월 노트는 `[자동] 월 개근 상점 (YYYY-MM)`이다. 기록 날짜는 해당 기간 마지막 관리일이다. 월 경계 주는 마지막 관리일이 속한 달에 집계한다.
- 같은 기간 재계산은 기록 ID를 유지한다. 출석 수정으로 자격이 깨지면 회수하고 회복하면 재지급한다. 자동 주·월 노트와 `ruleId=null`인 기록만 관리한다. 수동 기록과 다른 지점은 보존한다. DB에서는 직렬별 트랜잭션 잠금으로 동시에 저장해도 중복 지급을 막는다.
- 현재 재원 상태나 좌석 배정이 바뀌어도 해당 기간 출결이 개근이면 과거에 달성한 상점을 유지한다. 현재 학생 상태로 과거 개근을 취소하지 않는다.
- 관리자 확인 정책이 켜진 출결 벌점은 후보만 계산한다. 출석을 정정한 뒤 관리자 검토 화면에서 재확정하면 기존 종일·교시 벌점을 최신 후보로 교체한다. 개근 상점은 관리자 벌점 확정과 별개로 자동 지급·회수한다.
- 마이그레이션/기본 목 데이터는 주·월 0, 일일 꺼짐이다. 설정값 0은 자동 부여 중지이며, 해당 기간을 다시 계산하면 이전 자동 지급분도 회수한다. 전 기간 소급 재정산은 실행하지 않는다.
